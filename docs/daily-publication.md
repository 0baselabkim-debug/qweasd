# 일일 수집과 검증 후 웹 반영

기존 Streamlit 앱과 `main` 브랜치의 DuckDB 스냅샷을 계속 사용합니다. API 키는 GitHub Actions의 기존 `KIS_APP_KEY`, `KIS_APP_SECRET`만 읽습니다. 웹앱에는 키를 전달하지 않습니다. 기존 KRX·OpenDART 수집 코드는 유지합니다.

## 실행 순서

1. `.github/workflows/daily-dashboard.yml`이 한국시간 평일 **20:30**에 시작을 시도합니다. GitHub 예약 실행은 지연될 수 있습니다. **23:30**에는 미완료 날짜만 재시도합니다. 이미 게시한 날짜는 수집과 게시를 건너뜁니다.
2. KIS 공식 휴장일 조회 `CTCA0903R`로 거래일을 확인합니다. 휴장일은 새 날짜의 데이터를 만들지 않습니다. 체크포인트를 이용해 같은 날짜의 휴장일 조회를 반복하지 않습니다.
3. 공식 마스터의 보통주·시장·상장일·거래정지 상태와 **그날 관측한 업종**을 보관합니다. 당일 관측 마스터 없이 자정을 넘긴 최초 실행은 이전 날짜의 업종 구성을 추정하지 않고 중단합니다.
4. KIS `J=KRX`에서 날짜가 명시된 수급, 수정주가(`FID_ORG_ADJ_PRC=0`), 시총 검증용 현재가를 수집합니다. 수급은 백만원을 원으로 환산합니다. 시총은 종가·거래량·마스터 주식수·단위를 대조하고, 다음 달력일 09:00 이후 응답은 거부합니다. 지수는 KOSPI `0001`, KOSDAQ `1001`입니다.
5. 거래정지·명시적인 당일 거래량 0·공식 상장폐지일이 확인된 종목은 평가에서 제외합니다. **옛 날짜 반환이나 API 오류 자체를 거래 없음으로 분류하지 않습니다.** 기존 상장폐지 5개는 보존된 공식 응답을 재사용하며, 코드가 재사용되어 새 상장일이 생기면 옛 폐지일을 적용하지 않습니다.
6. 전체 대상의 성공 또는 근거 있는 제외가 모두 설명되어야 후보 DB를 만듭니다. 날짜·금액/수량 단위·중복·시총 일치·기준지수를 검사하고, 기존 수급·재무·업종·원시 시세 보존을 SQL로 대조합니다. 수정주가는 공급자 응답의 관측 시점 자료로 갱신하되 원시 종가를 덮어쓰지 않습니다.
7. 평가 및 테스트를 통과하면 DB·manifest·검증 결과·완료 기록을 **한 Git 커밋**으로 게시합니다. Streamlit이 해당 변경을 읽고 데이터 버전에 따라 캐시를 갱신합니다. 동시 변경으로 push가 거부되어도 기존 게시 자료는 유지됩니다.

## 보존과 실패 처리

- `data/daily-YYYYMMDD` 브랜치: 수집 성공/제외/실패 체크포인트. 성공 종목을 전체 재수집하지 않습니다.
- `snapshot/publication-ledger.json`: 거래일별 정상 게시 1회 기록, 실행 ID·실제 게시 시각·데이터 해시.
- 후보 검증 결과: 실제 예정/시작/완료 시각과 수집 실행 ID. 원본 체크포인트도 수신 시각을 보존합니다.
- 데이터 검증 실패, 과거 값 변경, 날짜 불일치, 기준지수 누락, 기존 업종 매핑 소실 또는 평가 가능 수 급감은 게시를 막습니다. Git에 남은 이전 정상 DB와 웹 기준일을 유지합니다.
- 자료가 충분하지 않은 신규상장 종목이나 재무 결측은 점수를 보류합니다. 가중치를 재분배하지 않습니다.
- 수급의 **공급원 최종 확정 시각은 미검증**입니다. 20:30은 실행 시도 시각이며 ‘최종 확정 시각’으로 표시하지 않습니다.

## 섹터 이력

확인된 업종 구성은 2026-10-14부터이며, 이전 날짜로 소급하지 않습니다. 앞으로 날짜별 관측을 저장합니다. 평가에 필요한 구성·가격·시총·수급·지수 관측이 모두 충족된 섹터만 기존 배점 40/30/20/10으로 평가합니다. 5일 대 이전 20일 거래 활성도에는 25거래일이 필요합니다. 기간이 지났다는 이유만으로 결측을 채우거나 자동 확정하지 않습니다.

## 운영 시간과 사용자 조치

현재 약 2,430개 평가 대상에 대해 수급·수정주가·시총 검증을 종목당 3회 조회하고, 전체 호출 간격은 1.05초 이상으로 제한합니다. 이론적 최소는 약 128분이며 정지 종목 확인·네트워크·재시도로 더 걸릴 수 있습니다. 이는 **새 일일 경로의 추정치**이고, 실제 완료 시간은 실행 기록으로 확인합니다. 공개 저장소의 표준 GitHub Actions runner를 사용하며 새 유료 서비스를 추가하지 않았습니다.

일반 사용자는 앱을 새로고침하면 됩니다. 실패 내역은 앱의 **수집·게시 실행 상태** 버튼 또는 GitHub 저장소 → **Actions → Daily validated dashboard refresh**에서 확인할 수 있습니다. 수동 재시도가 필요한 경우 **Run workflow → collect → Run workflow**를 사용합니다. 코드를 수정하거나 키를 재발급할 필요는 없습니다.

`verify_saved`는 보존된 실제 응답으로 후보 작성·검증·게시를 검증하는 개발용 모드입니다. 공식 거래일 API만 조회하며 전체 수급을 재수집하지 않습니다. 미래 거래일의 전체 운영 성공을 증명하는 모드가 아닙니다.

## 이번 실제 재조회에서 발견한 차이

2026-10-14 자료를 재조회한 수정주가의 최신 종가가 기존 관측과 2,042종목에서 달랐습니다. 대표 3종목을 수정주가·일반 종가·수급 API로 다시 호출했을 때 현재 응답끼리는 일치했고, 외국인 순매수 금액과 수량은 기존과 같았습니다. 수정·일반 옵션이 같아 기업행위에 따른 단순 주가 조정이라고 단정할 수 없습니다. 원인은 미확정입니다.

원시 종가·시총·수급·기존 종목 점수를 유지하고, 새 수정주가 관측은 출처와 함께 보관하되 `adjusted_price_conflicts`의 날짜·종목이 포함된 섹터 수익률은 보류합니다. 기존 날짜만 재처리하는 `verify_saved`는 기존 관측 변경과 신규 종목·날짜 추가를 거부합니다. **신규 날짜의 수집에서는 수급·현재가·수정주가 최신 종가가 일치하지 않으면 게시하지 않습니다.** 이는 불일치 자료를 정상으로 덮어쓰는 예외가 아닙니다.
