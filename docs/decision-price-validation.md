# 검증된 기술지표 입력과 보조 가격 수집

기존 수급 DB, v2/v3 브리핑, UI, 18:30/21:00 정규 수집은 변경하지 않는다.
공식 대조를 통과한 가격은 독립 `snapshot/decision-support`에만 사용한다.

## 증거와 판정

- 정규 수집 체크포인트는 최초 관측이다. 이후 KIS 원주가(1)·수정주가(0), KRX 응답은 각각 별도 해시로 보존한다.
- 장기 표본은 동일 조회 묶음의 두 KIS 가격 기준, 공식 KRX 시가·고가·저가·종가·거래량·거래대금이 모두 정확히 일치해야 한다. 허용 오차는 없다.
- 공식 지수 응답의 거래일을 사용한다. 주말을 빼서 거래일을 만들거나 결측 일봉을 보간하지 않는다.
- 과거 정규 DB와 다른 후보는 6필드 대조를 통과해도 DB를 교체하지 않는다. 분석 JSON에 원본과의 차이, 후보 출처·관측 시각을 남긴다.
- 공식 KRX 원주가와 수정주가가 다르면 보류한다. 가격 조정과 기업행사 근거를 임의 추정하지 않는다.
- `flng_cls_code=05`는 공식 KIS 명세상 중간·분기 배당락이다. 해당 사건의 조정 근거 미검증 시 이를 가로지르는 기간은 보류한다. 이후 각 날짜를 독립 검증할 수 있으면 연속 후속 구간의 지표만 제공한다.
- `mod_yn=Y`는 명세상 체결이 없어 시가가 없는 상태다. 이를 기업행사라고 분류하지 않으며 해당 일봉은 지표 입력에서 제외한다.
- 운영 대조 통과와 공급자 최종 확정 표시는 다르다. `provider_finality=UNVERIFIED`를 유지한다. 사후 관측은 당시 투자 가능 신호로 인정하지 않는다.

## 증분 연결

`history.continuation`은 저장한 검증 묶음과 새로운 정규 체크포인트의 겹치는 **20거래일 이상 전체 OHLCV**가 정확히 같을 때만 연결한다. 새로운 날짜마다 다시 공식 KRX와 비교한다. 과거 종가 한 필드만 갈아 끼우지 않는다. 겹침 충돌, 조정 표시, 누락, 달력 불일치는 연결을 중단한다. 이전 정상 자료는 증거로 남고, 이전 날짜 자료를 당일 값으로 표시하지 않는다.

## 호출과 자동화

`decision-price-evidence.yml`은 기존 정규 수집 및 가격 복구의 성공 완료 이벤트와 수동 실행만 받는다. **새 cron은 없다.** 기존 `kis-validation-auth` 잠금과 운영 작업 우선 순위를 사용한다.

- 자동 경로: 최신 정상 게시본의 다음 날 이후 KRX 두 시장만 조회. 실행당 최대 2회, KST 하루 최대 4회(실패 포함). KIS 인증·시세·수급·장기 수집은 자동 경로에서 금지한다.
- 18:00~23:00, 당일/미래 기준일, 운영 작업 실행·대기 중이면 요청하지 않는다. 따라서 저녁 수급 게시 직후 기술지표까지 확정됐다고 보장하지 않는다. 다음 날 기존 가격 복구 이벤트가 참조자료 확보 기회를 제공한다.
- 정상 자료는 재사용한다. 미확보일 때 수급 게시를 막지 않으며 기술지표는 null/보류로 남는다.
- 초기 수동 이력 검증: 전체 예산 300회, 배치당 최대 20회·600초, 1.05초 간격. 인증·실패·실제 재시도를 모두 계수한다. 자동 재시도는 끄고 다음 실행에서 정상 응답을 재사용한다.
- 별도 원격 요청 예약을 **HTTP 전에** 저장한다. 응답 원장과 원본은 Git 증거 브랜치와 artifact에 이중 보존한다. 종료 상태가 유실되면 예약량을 소비한 것으로 취급하며 실행을 나눠 한도를 초기화하지 않는다.
- 최초 지수 보완 실행 `39736095088`은 조회 단계 성공 후 증거 게시에 실패했고 로그 다운로드도 403이었다. 실제 물리 횟수를 단정하지 않고 최대 20회를 별도 차감했다. 이는 정상 관측 원장 횟수와 구분한다.

증거: `evidence/decision-price-source` 브랜치의 `auxiliary-prices/`.
분석 생성: `decision-support.yml`; 시장 인증정보 없이 저장된 증거만 읽는다.
정상 생성·원천 합계 대조 후 분석 DB·index·shards·validation을 단일 Git 커밋으로 게시한다. 동시 main 변경 시 강제 push하지 않고 이전 정상 게시본을 유지한다.

## 수동 실행·검증

Actions → **Bounded decision price evidence** → Run workflow → main:

1. `reference`: 최신 정상 게시일의 KRX 두 시장(캐시가 있으면 요청 0회).
2. `pilot`: 세 표본의 수정·원주가 2페이지씩, 지수 3페이지씩. 종목 API는 실제 100행, 지수 API는 실제 50행이다. 성공 페이지는 재사용한다.
3. `history-references`: 지수의 최근 121거래일 중 누락된 시장·날짜만 최대 20회. 남으면 다음 수동 실행으로 이어간다.

현재 표본은 178320·000720·064400이다. 전체 2,430종목의 장기 KIS 이력을 재수집하는 기능은 없다.

오프라인 재현:

```sh
python -m pytest -q
python scripts/build_decision_support.py --fetch-checkpoints
python scripts/build_decision_support.py --verify-only
python reports/decision-price-validation/audit.py
```

독립 검증은 pandas rolling/shift, 별도 true-range와 seeded EWM으로 SMA·기울기·일목·Wilder ATR을 대조한다. 기존 원본 수급 SQL 합계 검증은 그대로 유지한다. ATR로 자동 손절가나 매수·매도 주문을 만들지 않는다.
