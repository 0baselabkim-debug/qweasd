# 4차 개발: 공시와 운영 이력

시장·수급 DB와 기존 연간 종목 점수는 보존한다. 공시 수집은 별도 `snapshot/corporate.duckdb` 및 압축 상태 파일에 저장하며 공개 앱은 키 없이 이 자료를 읽는다. 공시일이 조회 기준일 이후인 재무는 표시하지 않는다.

## 실제 검증과 초기 확대

2026-10-15 소규모 실제 검증: 10기업, 연간·반기 20보고서, 41호출/501.63초. 원문 실패 2건만 2호출/59.82초로 재시도하여 복구했다. 연간 재무 2,415건은 기존 DB에서 그대로 보존하고 새 반기 재무 10건을 추가했다. 신규 7기업의 실제 제조·판매 문맥을 검토해 테마 기업은 39→46, 소속은 42→50으로 확대했다. 반도체 13, 로봇 10, 전력 인프라 9, 원전 8, 방산 6, AIDC 4(기업 중복 있음). 나머지 미조사는 해당 없음으로 간주하지 않는다.

로컬 표본 비례 단순 추정은 전체 약 1만 호출, 34시간이었다. 이후 실제 GitHub Actions 2기업 검증은 8호출/14.28초, 4보고서 수집·게시 성공으로 더 빨랐다. Actions 표본 기준으로 총 1만 호출·약 5시간 전후, 120기업씩 하루 4회 처리 시 약 5~6일에 걸친 초기 조사를 예상한다. 추가 2기업을 포함해 현재 12기업의 사업보고서·반기보고서 24건과 신규 반기 재무 12건이 게시되었다. 실제 전체 공시 목록은 시장별 일괄 조회하므로 호출량은 감소할 수 있고 원문 크기·재시도에 따라 소요시간은 달라진다. 실행당 최대 600호출·35분·120기업, 하루 4회로 나누며 초기 완료 일정은 실제 수신 시간·실패율에 따라 갱신한다. 공개 저장소의 표준 ubuntu-latest 호스팅 러너만 사용한다. 유료 러너/API를 추가하지 않는다. 실패·미완료만 이어받는다. 이는 예상이며 전체 조사 완료 실적이 아니다.

## 수집과 검증

- 신규 공시 목록은 KOSPI/KOSDAQ, 정기 공시, 90일 이하 구간, 페이지 단위 수신. 완료 구간을 저장하고 이후 7일을 겹쳐 정정 공시도 재확인한다. 공시 접수번호로 중복을 막는다.
- 첫 조사에서는 기업별 최근 사업보고서와 최근 중간 보고서를 처리한다. 이후 새로운 분기·반기·사업보고서와 정정 접수번호를 추가한다. 과거 모든 분기를 소급 확보한 것은 아니다.
- 사업의 내용 구간만 추출한다. 6개 테마 키워드는 후보 탐색용이며 자동 확정하지 않는다. 기존 검증 문장이 새 보고서에도 정확히 존재할 때만 자동 재검증한다. 신규 확정/해당 없음/제외 결정은 원문 인용·해시·검토일·검토자·사유와 변경 전후 이력을 남긴다. 원문 부재, 키워드 미검출은 검토 필요다.
- 새 공시의 사업 근거가 검토 필요이면 새 분류 기준일 이후 기존 확인을 자동 승계하지 않는다. 과거 시점의 분류는 유지한다. 당일 최신 화면의 테마 분류 기준일과 수급 기준일을 각각 표시한다.
- 반도체 테마 정의에는 실제 반도체 공정·검사 장비와 부품 사업을 포함한다. 고객사 관련 뉴스나 산업 전망만으로 포함하지 않는다. 풍력은 사업보고서에서 관찰되는 추가 테마 후보이며 사용자 승인 전 적용하지 않는다.
- 재무는 접수번호·회계연도·보고서 코드·KRW를 대조한다. CFS를 우선, 자료 없음(013)일 때만 OFS를 조회한다. 연결/별도는 별도 레코드다. 비12월 결산은 보고기간 검증 전 보류한다.
- 중간 손익 누적값과 개별 분기값을 분리한다. CF는 누적값이다. 누락된 누적값을 개별 분기로 대체하지 않는다. 동일 기간의 전년 비교값이 있을 때 성장률을 계산한다. 중간 기간 PER·ROE는 검증된 TTM 미구성으로 보류한다. PBR은 해당 기간말 지배주주 자본(CFS)/별도 자본(OFS) 및 표시된 시총 기준일을 사용한다.
- 기존 2025년 연간 평가 1,161종목과 모든 가중치는 유지한다. 새 분기 자료를 기존 평가에 섞거나 연율화하지 않는다.

## 예약·보존·게시

공시 수집은 KST 02:17/08:17/14:17/18:17, 시장 수집은 평일 20:30/23:30을 유지한다. 공시는 `corporate-disclosures`, 시장은 `kis-validation-auth` 직렬 대기열을 사용한다. 공시가 시장 재시도 대기 작업을 교체하지 않는다. 같은 시장 수집끼리는 동시 실행하지 않는다. 예약 시작은 GitHub 지연 가능성이 있다.

시장 및 공시별 체크포인트를 별도 브랜치에 저장한다. 공시는 이미 게시된 공시·재무·변경 이력을 포함하는 호환 체크포인트만 복구한다. 게시 전 기존 레코드 보존·기간·단위·근거를 검사한다. main 갱신 경쟁 또는 검증 실패 시 기존 공개 스냅샷을 유지한다. 체크포인트로 다음 실행에서 이어받는다. 정상 스냅샷을 Git commit으로 게시하면 Streamlit이 반영하고 데이터 해시로 캐시를 갱신한다.

시장 실행마다 예정 시각, 실제 runner 시작, 수집 시작/종료, 성공·제외·실패 수와 목록, 게시 시각을 `operations/market-runs`에 기록한다. 실제 collect 모드의 정상 게시일만 서로 다른 3거래일 검증으로 집계한다. 저장 자료 리플레이·기존 게시일 건너뛰기·실패·미래 날짜는 제외한다. 아직 3거래일 성공은 확인되지 않았다.

## 정식 섹터 평가

5·20일 수급 순위, 현재 구성 기준 수급 부분 점수 70점, 정식 종합 100점은 분리 표시한다. 기존 계산 엔진의 정식 점수를 화면에 연결했으므로 조건을 충족하는 업종부터 자동 표시한다. 가중치 40/30/20/10은 유지한다.

과거 업종 구성을 확인할 새로운 공식 원천은 확보하지 못했다. 2026-10-14 이전 구성을 소급 생성하지 않는다. 일일 수집은 관측일의 실제 구성을 저장한다. 실제 구성·조정주가·시총·시장지수·25거래일 거래대금 등 조건 미충족은 계속 보류한다. 현재 50업종의 정식 종합 점수는 모두 보류다.

동일 과거 날짜에 KIS 공식 J(KRX)/NX(NXT)/UN(통합)을 3종목 실측했다. 보존 종가 삼성전자234,500/SK하이닉스1,425,000/NAVER180,000은 NX·UN 종가와 일치했고 J는232,000/1,419,000/179,400이었다. 각 종목의 UN 순매수 금액·수량은 J+NX와 일치했다. 2,042종목 모두 같은 원인이라고 단정하지 않으며 원본과 수급 48,567행 및 평가를 변경하지 않는다. 가격 문제는 수급 추이 기능을 중단시키지 않는다.
