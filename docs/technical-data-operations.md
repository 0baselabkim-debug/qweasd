# 기술 분석 데이터 운영

기존 수급·재무 DB, 기술 판정 수치, 매매일지 개인정보를 분리한다. 기술 데이터만으로 주문을 실행하지 않는다.

## 저장과 실행

- `technical/market/<종목코드>.json.gz`: 종목별 최근 320거래일 KRX 수정 OHLCV와 동일 날짜 원본 수급. 원·주 단위. 종목코드는 파일과 레코드에 보존한다.
- `technical/collection-state.json`: 종목별 마지막 시도, 완료 기준일, 실패/미확보 유형. 최근 실행 요약 60개만 유지한다.
- `technical/rejected/`: 새 자료가 기존 정상 자료보다 부족하거나 부적합하면 후보만 별도 보관. 기존 정상 파일을 덮어쓰지 않는다.
- `technical/reference/`: KRX 공식 일별 시세 대조 자료. 시장별 최신 한 파일만 유지한다.
- `technical/corporate-actions.json.gz`: 공개 예탁원 일정 응답. 페이지·기간의 완전성이 확인되지 않으면 전체 기업행사 검증을 통과시키지 않는다.
- 기존 `technical/pilot.json.gz` 3종목 시험 자료는 보존한다. 앱은 같은 날짜의 확대 캐시를 우선 조회한다.
- 파일은 임시 파일 작성 후 교체한다. 공개 일봉/체크포인트만 Git에 게시하며 개인 기록·보유종목 큐·개인 분석 결과는 Supabase 전용이다.

최초 수집은 7개 우선 종목부터 시작한다. 이후 기존 보유 자료의 새 날짜 갱신과 신규 종목 과거 수집을 번갈아 처리한다. API 간격은 기존 1.05초, 일봉 한 페이지 최대 100개다. 배치 최대 600종목이나 25분이 지나면 다음 종목부터 중단하고 체크포인트를 게시한다. 실제 종료까지 진행 중인 한 종목의 시간이 더 걸릴 수 있다.

일일 작업은 평일 한국시간 23:45, 다음 날 00:45·01:45·02:45에 이어받는다. 기존 수급 게시 성공 이벤트도 유지한다. 모든 KIS 작업은 기존 `kis-validation-auth` 동시성 그룹을 공유한다. 기존 20:30 수급 수집·23:30 재시도 워크플로는 변경하지 않았다. GitHub 예약 지연/대기 취소가 발생해도 다음 실행이 영구 체크포인트를 읽는다. 예약 등록은 미래 실행 성공의 증거가 아니다.

수동 진행: 저장소 → Actions → **Separate technical OHLCV cache** → Run workflow → `public`, 배치 수 입력. `evidence`는 7종목 시장 범위·공식 문서·기업행사 점검만 실행한다. 사용자가 명령어나 소스 코드를 수정할 필요는 없다.

## 증분 갱신과 재시도

이미 같은 수급 기준일까지 수집한 종목은 건너뛴다. 새 날짜에는 기존 마지막 10개 일봉과 겹치는 구간을 조회한다. 과거 OHLCV 변경, 조정 사유, 중간 거래일 누락/겹침 부재가 있으면 전체 창을 다시 조회해 서로 다른 수정 기준을 섞지 않는다. 정상적인 경우 신규 일봉과 겹침 확인만 수행한다.

API/스키마 오류, 부족한 일봉, 신규상장, 마지막 날짜 지연, 거래 없음은 별도 상태다. 113개 기존 제외 종목은 원래 제외 사유대로 유지한다. 기업행사나 거래정지는 빈 날짜를 0으로 채우지 않는다. `collected`는 일봉 확보 상태이며 신호 판정 가능 상태와 다르다.

개인 작업은 최대 10분으로 제한해 미연결·실패가 공개 수집을 막지 않게 한다. 비공개 캐시를 재사용하고 최초 매수일 전 160거래일을 포함하도록 조회 길이를 늘린다(최대 5,500일봉; 부족하면 보류). 개인 자료가 있는 경우에도 공개 저장소에 매수일·수량·평균단가·로그인 정보나 보유종목 목록을 게시하지 않는다. Supabase 실제 운영은 별도 인증 및 권한 검증이 필요하다.

## 가격 범위와 검증 수준

공식 KIS 명세: `J=KRX`, `NX=NXT`, `UN=통합`; `FID_ORG_ADJ_PRC=0` 수정, `1` 원주가. 기존 종가와 비교할 때는 같은 날짜 원주가끼리 비교한다. 기술 분석에는 J 수정 일봉만 사용한다. 수급은 보존된 J 원화 금액을 재사용하며 대표 종목을 실제 API로 재대조한다.

- `CROSS_VALIDATED_DAILY`: 동일 날짜 KRX 공식 일별 종가와 KIS 원주가 일치. 이것은 최종 확정 표시에 해당하지 않는다.
- `UNVERIFIED`: 최종 확정 근거 미확보. 경과 시간이나 반복 응답만으로 `VERIFIED`로 바꾸지 않는다.
- 기존 값이 현재 통합 시세와 일치하면 근거를 기록해 KRX 기술 원천과 분리한다. 기존 요청 로그와 공급자 응답의 과거 경로까지 증명했다고 주장하지 않는다. 어떤 범위와도 일치하지 않는 차이는 계속 미해결로 남긴다.
- KIS 일봉의 `prtt_rate`는 기준가/전일종가, `revl_issu_reas`는 재평가 사유다. 이것만으로 주식분할·권리 변동의 완전한 명세를 확보했다고 간주하지 않는다. 보유 수량과 평균단가는 자동 변경하지 않는다.

공식 최종 확정 및 필요한 기업행사·거래비용 검증이 미완료인 동안 매수·매도는 보류된다. 계산 가능한 관측 지표와 보류 사유는 기존 상세 화면에서 확인할 수 있다.

## 저장 용량

공개 일봉은 종목당 320행과 최신 캐시로 제한하고 gzip 압축한다. 실행 기록은 60개, 거절된 후보와 기준 자료는 최신 파일만 유지한다. 실제 캐시 용량은 `technical/summary.json`에 기록한다. Git 이력 자체는 누적되므로 전체 수집 후 실제 증가량을 확인해야 한다. 현재는 공개 저장소의 표준 GitHub-hosted runner를 사용하며 유료 서비스·대형 runner·새 요금제는 추가하지 않는다.
