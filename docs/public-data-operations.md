# 공개 데이터 운영

앱 메뉴는 매크로 지표와 수급 필터 두 개다. 매수·매도 판정, 개인 계정 및 보유종목 저장 기능은 없다. 재무정보는 수치와 공시 사실만 표시한다.

## 일일 수집과 유동성 증거

기존 평일 한국시간 18:30 정규 시장 수집, 21:00 실패분 재시도, 매크로 및 DART 갱신은 유지한다. 예약 시각은 실제 시작을 보장하지 않는다.

`liquidity-recovery.yml`은 종전 인증 직렬화 그룹 `kis-validation-auth`를 유지한다. 매회 최대 6개 날짜·종목, KIS 인증·재시도를 포함한 물리 요청 최대 60회, 최소 1.05초 간격, 240초 이후 새 요청 시작 금지를 적용한다. 최대 두 날짜의 KRX 자료를 확인한다. 자료 미확보·실패 작업은 날짜별 대기열과 백오프에 남는다. 이미 게시된 동일 날짜 증거는 재수집하지 않는다.

복구 대상은 DB의 실제 미해결 가격 충돌 중 동일 날짜 원본 가격과 20거래일 수급이 있는 관측이다. 매매 가이드의 160~320일 자료는 요구하지 않는다. 한 번에 동일 KIS J 기준의 25거래일 수정 시세, 해당 날짜 원주가, 20거래일 외국인 수급 원응답을 확인한다. 같은 날짜 KRX 공식 OHLCV 6개 항목·원주가·날짜·시장·단위·해시 검증을 모두 유지한다. 관측일이 한국시간 기준 다음 날짜인 자료만 일별 운용 검증에 사용하며, 공급자 최종성은 UNVERIFIED로 남긴다. 이것은 공급자의 최종 확정 표시가 아니다.

거래 활성도는 최근 5거래일 평균 거래대금 / 직전 20거래일 평균이며, 모든 구성종목의 25거래일이 완전한 섹터만 게시한다. 실제 0과 결측을 구분한다. 원본 DB 가격은 덮어쓰지 않는다. 날짜별 원본 거래량·거래대금과 검증 후보가 일치할 때 해당 관측만 사용 가능하게 한다. 과거 조회에 최신일 증거를 빌려 쓰지 않는다.

중단된 응답은 내용 해시로 보관한다. 재개 시 수정 시세와 원주가 두 기준 응답이 동일할 때만 나머지 응답을 재사용한다. 새 가격 기준이 다르면 전체 25일 창을 다시 검증한다. 후보·수락·Git 게시·웹 반영은 각각 구분한다. 게시 충돌 시 별도 evidence 브랜치에 보존하며 정상 main 데이터를 덮어쓰지 않는다.

## 보관

`liquidity/`는 활성 증거·응답·체크포인트다. `audit-archive/`는 이전 원본 관측과 게시본을 바이트 단위로 보존한 압축 보관소다. `inventory.json`에 원본 경로·SHA256·압축 파일이 기록된다. 앱이나 수집기는 이 보관소를 읽지 않는다. 이전 기술지표가 포함된 원본은 감사 증거 보존 목적이며 새로 계산·갱신하지 않는다. Git 이력은 재작성하지 않았다.

현재 DB와 바로 이전 정상 게시 세대는 기존 fallback 방식으로 이용한다. 더 오래된 세대는 압축 보관소와 Git 이력에 있다. 현재 DuckDB 원본 8개 테이블, 재무·공시·테마 이력은 보존한다.

## 외부 개인 저장소 정리

외부 개인 데이터에는 접근하거나 삭제하지 않았다. 실제 Supabase 프로젝트를 만들었다면 필요한 개인 기록을 먼저 내보내 보관한다. 이후 사용자가 Streamlit Community Cloud → 앱 메뉴 → Settings → Secrets에서 Supabase 항목을 제거하고, GitHub 저장소 → Settings → Secrets and variables → Actions에서 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 등 개인 저장소 전용 항목을 삭제할 수 있다. KIS·KRX·DART·FRED·ECOS 키는 유지한다. Supabase 프로젝트 삭제는 데이터 보관 여부를 결정한 후 사용자가 별도로 수행한다.
