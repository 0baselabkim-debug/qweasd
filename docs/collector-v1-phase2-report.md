# 2단계 실연결 검증 결과 — 2026-10-26

## 1. 개발 상태

대상 브랜치: `feat/market-data-collector-v1`. 시작 HEAD는 `8e88c8956760ac7e35d7c707b013affb595a34bb`이며 실제 로컬 커밋이다. 원격 `main`은 읽기 전용 `git ls-remote`에서 `7161d62c4b14bd48b4d8a93da44b8528ca150629`로 확인했다. 조사 당시 기능 브랜치는 원격에 없었다. 기능 브랜치 등록 작업의 최종 결과는 작업 응답과 로컬 `data/collector-v1-phase2-20261023/report.json`에 기록한다. main 병합/배포는 하지 않는다.

기존 커밋의 9개 추가 파일을 검토했고, 개인키/GitHub 토큰/AWS 키 형식 및 현재 주입된 인증값과 일치하는 내용은 없었다. 검사는 모든 형태의 비밀값 부재를 보증하지 않으며, API 키를 환경에서만 읽는 구현도 별도로 검토했다. 인증값은 출력하거나 복사하지 않았다.

수정 전 관련 회귀 테스트: **100개 통과 / 2.36초**. 제한 강화 후: **105개 통과 / 2.19초**. 신규 5개는 인증/네트워크 오류 시 후속 호출 중단과 재시작 후 20회 누적 제한을 검증한다. 모두 오프라인 검사다.

실행 CLI는 `.venv/bin/python -m collector_v1 --root <시험디렉터리> ...`이며, 일반 사용법은 `collector-v1.md`를 참고한다. 이번 고정일 시험은 아래 사유로 실제 collect를 실행하지 않았다. 일반 예시의 10월 26일이나 다른 종목으로 대신 수집하지 않았다.

코드와 요청의 차이를 확인하여 다음만 수정했다.

- CLI의 기존 프로세스당 20회/root 누적 300회를 **동일 root 누적 20회**로 제한했다. 인증/실패/결과 불명 호출도 포함한다. 범용 Budget 클래스의 기본값은 그대로지만 CLI는 20을 명시한다.
- 기존 배치는 오류 후 다음 작업을 계속했다. CLI는 첫 수집 오류에서 중단하고, 성공 원문/실패 상태/미실행 작업을 남긴다.
- 즉시 자동 재시도는 기존에도 없었으며 유지했다. 요청 전 예산 기록과 최소 1.05초 간격도 유지한다.
- 워크플로 입력 설명과 문서를 실제 CLI 제한에 맞췄다. 운영 데이터/예약 정의는 수정하지 않았다.

서로 다른 root/프로세스/외부 수동 진단의 HTTP를 합산하는 전역 한도는 없다. 이번 시험은 하나의 독립 root만 사용하고 외부 제공처 HTTP를 전혀 시작하지 않았으므로 총 20회 조건을 넘지 않았다. 추후 DART/매크로를 별도 root로 실행하며 이 제한을 우회하면 안 된다.

## 2. 인증 및 연결 상태

현재 머신에서 이름/존재 여부만 검사했다. GitHub Secrets의 값을 추출하지 않았다.

| 제공처 | 현재 머신 인증정보 | 네트워크 관측 | 이번 제공처 HTTP 시도 | 결과 |

| KIS | KIS_APP_KEY, KIS_APP_SECRET 모두 없음 | 저장 설정에 호스트 없음; 직접 연결 NOT_RUN | 0 | BLOCKED |
| KRX | KRX_API_KEY 없음 | 저장 설정에 호스트 없음; 직접 연결 NOT_RUN | 0 | BLOCKED |
| DART | DART_API_KEY 없음 | 저장 설정에 호스트 없음; 직접 연결 NOT_RUN | 0 | BLOCKED |
| ECOS | ECOS_API_KEY 없음 | 저장 설정에 호스트 없음; 직접 연결 NOT_RUN | 0 | BLOCKED |
| FRED | FRED_API_KEY 없음; 공식 CSV는 키 불필요 | 이전 프록시 403, 허용 설정 변화 없음; 재호출 안 함 | 0 | BLOCKED |

현재 저장 네트워크 정책은 restricted, custom egress_rules는 비어 있다. 패키지 preset에 위 제공처는 없다. 이는 저장 설정 관측이며 각 호스트의 새 연결 실험을 대신하지 않는다. 현재 머신에 시장 API 키가 없어 요청을 시작하지 않았다.

GitHub HTTPS Git 읽기는 플랫폼 인증으로 성공했다. GH_TOKEN은 존재하지만 이것이 시장 API 키 주입이나 GitHub API 권한을 뜻하지 않는다. GitHub API를 통한 Secrets 이름 및 워크플로 조회는 `Forbidden`으로 실패했다. 따라서 **원격 Secrets 존재 여부는 UNKNOWN**이며, Secrets가 없다고 단정하지 않는다. Forbidden의 발생 주체가 API 권한인지 중계 계층인지 이 결과만으로 확정하지 않는다. API 재시도는 오류 출처 진단까지만 수행했고 제공처 API를 우회하지 않았다.

현재 원격 main 커밋에는 `.github/workflows/collector-v1.yml`이 없다. `workflow_dispatch`는 기본 브랜치 등록 요건이 있으므로 기능 브랜치 push만으로 실행 가능하다고 판단하지 않았다. GitHub API로 등록 상태를 확인할 수도 없어 dispatch를 시도하지 않았다. main에 워크플로를 추가하거나 기존 수집 워크플로로 우회하지 않았다. 독립 로컬 실행 역시 인증정보가 없어 차단됐다.

## 4. 오류 및 제한사항

1. **시장 인증정보 부재:** Codex 환경 설정의 비밀정보 주입 또는 독립 실행 환경의 안전한 환경 변수 설정이 필요하다. GitHub Secrets를 쓰려면 저장소 Settings → Secrets and variables → Actions에서 동일 이름의 존재 여부를 사용자가 확인해야 한다. 값을 채팅에 제출할 필요는 없다. GH_TOKEN으로 시장 인증을 대체하지 않는다.
2. **네트워크 접근 설정:** 환경 설정에서 필요한 호스트 `openapi.koreainvestment.com`(HTTPS 9443), `data-dbg.krx.co.kr`, `opendart.fss.or.kr`, `ecos.bok.or.kr`, `fred.stlouisfed.org`를 검토한다. 일반 master bootstrap은 `new.real.download.dws.co.kr`도 필요하다. GitHub API 확인에는 `api.github.com` 접근 및 해당 작업의 권한도 필요하다. 기존 허용 목록을 교체하거나 접근 제한을 우회하지 않았다.
3. **고정 과거일 모집단:** 현재 market CLI는 수집 당일 공식 master를 요구한다. 10월 26일 받은 master를 10월 23일로 소급하는 것은 `historical_universe_unverified`로 차단된다. 인증을 해결해도 10월 23일 원천·해시가 있는 적법한 master 증거가 별도로 필요하다. 사용자 지정 3종목만으로 과거 공식 분석 모집단이 검증됐다고 표시할 수 없다. 표본 API 원문만을 수집하는 별도 모드를 만들더라도 모집단 미검증과 게시 보류를 유지해야 한다. 이번에는 해당 우회 모드를 추가하지 않았다.
4. **실제 공급자 미검증:** API 접근 범위/과거일 반환/가격 충돌/기관 수량 제공 범위는 이번 작업에서 확인하지 못했다. 기관 금액 배율은 계속 미검증이며, 내부 검증을 통과하더라도 공급자 최종성 UNVERIFIED를 유지한다.
5. 인증/네트워크/합법적 실행 경로 또는 원천 근거가 바뀐 뒤에만 재시험한다. 같은 실패를 반복 호출하거나 날짜·단위·허용오차를 바꿔 통과시키지 않는다.
