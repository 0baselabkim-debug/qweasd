## 저장·복구·검증

`data/full-market-20261026/round`만 제공처 요청 원장을 갖는다. 회차별 별도 Actions 아티팩트에 round/asof/run ID/파일 해시를 기록한다. 이전 회차 보고서는 비교에만 쓰고 가격·수급 응답은 복사하지 않는다. 같은 회차의 성공 원문만 해시 확인 후 재사용한다. HTTP 시작 전에 append+fsync 원장에 차감하고, 실패/인증/결과 불명 시작도 센다. 큰 JSON 원장을 매번 재작성하지 않는다.

원문 bytes를 변경하지 않고 gzip 보존한다. 정상 HTTP 뒤 저장 실패는 동일 메모리 원문을 로컬 저장 재시도하며 API를 재호출하지 않는다. 네트워크/408/5xx는 5·10초, 429는 30·60초, 대상 날짜 미제공은 60·120초의 제한적 backoff를 적용한다. 3회 burst, 재개 포함 일반 작업 최대 6회 및 전체 HTTP/시간 상한을 적용한다. 명확한 권한/스키마/가격 충돌은 무작정 재시도하지 않는다. 알려진 토큰 만료 코드만 한 번, 최소 60초 후 재인증한다. 반복 장애는 circuit wait 후 제한적으로 확인한다. 실패 작업만 재개한다.

원주가 OHLCV 6필드는 KRX의 동일 코드·시장·날짜와 정확히 대조한다. 같은 회차에서 시장 참조가 갱신됐을 가능성이 있는 충돌은 시장별 최대 2회의 제한적 참조 refresh 후 기존 원문을 다시 검증한다. 충돌 값은 원문과 필드별 차이를 남기며 승인하지 않는다. 기관 금액은 원천 값만 보존하고 원화 금액은 null이다. source hash와 metadata observation ID, 실제 관측 시각을 연결한다.

파싱/교차검증을 통과한 행만 독립 실험 DuckDB에 일괄 기록하고 JSON과 전체 값/행을 대조한다. derived DB는 전체 payload 해시별로 보존하고 동일 파일을 재작성하지 않는다. 운영 DB/snapshot에 쓰거나 main에 데이터 commit/push하지 않는다.

항상 종료 seal+artifact 업로드를 시도한다. 호스팅 러너 강제 종료/디스크/업로드 장애로 **최신 아티팩트가 없으면** 사용량을 알 수 없으므로 회차 최대 예산을 보수적으로 점유한 것으로 보고 자동 재수집하지 않는다. 이전 아티팩트로 fallback해 0부터 재시작하지 않는다. 원문은 업로드 전 Secret 문자열 검사를 하며 의심되면 업로드를 차단한다. raw/원장/상태/DB/JSON/보고서는 7일 보존하고, 회차 상태는 80MB 크기 상한을 둔다.

## 비교·성능·보고

비교 키는 symbol/market/asof, 값 해시는 수급·기관 원천값·OHLCV·시총만 포함한다. 원천 JSON hash/관측 시각은 별도라 새 응답 시각만 달라져 값 변경으로 오판하지 않는다. null과 0은 다르다. 모집단/회차/날짜가 다르거나 빈 모집단이면 비교 불가다. 일부 자료만 같으면 PARTIAL_MATCH, 값이 다르면 VALUES_CHANGED, 두 회차 전체 대상이 내부 검증과 저장까지 COMPLETE이며 모두 같아야 COMPLETE_MATCH다.

매 회차 source/launcher commit, 설정 hash, 예약/실제/첫·마지막 HTTP/완료 시각, network wall time, rate/backoff/circuit 대기, 파싱·해시·압축·검증·DuckDB·JSON 시간, 처리량, 재시도/복구 건수와 미복구 사유를 기록한다. 중단으로 순수 네트워크 metrics를 잃으면 완전한 실측이라고 주장하지 않는다.

다음 회차 개선은 실제 원문 100개의 gzip 9/1 level을 재실험해 복원이 동일하고 처리시간 5% 이상 감소·크기 증가 25% 이하인 경우에만 적용한다. 효과가 없으면 baseline을 유지/복원한다. API 간격이나 검증은 바꾸지 않는다. 전체시간 차이는 공급자 지연 등의 영향도 있으므로 압축 설정의 인과적 개선으로 단정하지 않는다. 검증되지 않은 자동 소스 수정은 하지 않는다.

Job Summary와 다운로드 보고서 아티팩트, `[full-market-20261026] 네 회차 수집·복구·안정성 보고` GitHub Issue에 각 회차 예약/결과/복구 결과를 기록한다. 최초 완전 일치면 즉시 잠정 안정성 알림을 남기고 나머지 회차를 계속한다. 4차가 실제로 끝난 후 최종 보고를 만들며, 누락·실패 회차도 UNRESOLVED로 포함한다. 정확한 공식 확정 시각이나 영구적인 권장 운영 시각을 근거 없이 확정하지 않는다.

## 검증 및 현재 상태

오프라인 통합은 실제와 동일한 2,349종목 모의 HTTP 4,703회를 처리하며, 전체 크기/회복/재개/예산/빈 모집단/부분 일치/시각 지연/아티팩트 변조/마스터 원본 복원/소스 보호를 검사했다. 이전 표본 및 관련 회귀를 포함해 **163개 통과**다. 이는 실제 전체시장 성공이 아니다. 실제 결과는 예약 이후의 Actions/Issue/아티팩트에서 확인한다. 기존 suite의 예약 복원 기대값 5건은 관련 명령 밖이며 기존 예약을 되살려 맞추지 않는다.

이 문서와 기능 브랜치의 workflow는 배포 템플릿이다. 기본 브랜치의 launcher는 검증된 소스의 실제 full SHA로 `EXPERIMENT_SOURCE_SHA`를 치환한 파일 한 개만 사용해야 한다. 템플릿을 그대로 기본 브랜치에 등록하지 않는다.

## Actions 준비 단계 복구

얕은 checkout에서도 기존 pilot 제어 파일 불변 검사가 동작하도록 고정 baseline 커밋을 명시적으로 fetch한다. 시장 호출 단계가 모든 실행 시도에서 `skipped`였음을 GitHub Jobs API로 증명한 경우에만 이전 요청 수를 0으로 인정한다. 실제 호출 단계가 시작됐거나 job 기록이 불완전하거나 아티팩트 해시가 틀리면 이 예외를 적용하지 않는다. 호출 이력이 있을 수 있는 아티팩트 유실은 계속 전체 예산 소진으로 취급한다.

cron 지연 보완용 일회성 clock은 제공처 Secret 없이 Actions 상태 조회/dispatch만 수행한다. 네 단계 각각 355분 이하이며 지정 UTC 날짜가 지나면 새로 arm할 수 없다. 제어 파일 단독 커밋에서만 arm되고, 회차별 수집 마감·공유 잠금·원장 한도를 그대로 따른다. 최종 단계는 보고서 생성 후 실험 워크플로를 disable한다.
