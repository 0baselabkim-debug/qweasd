# 2026-10-29 승인 보완 수집

20:30 정기 Run 40870637994는 0 HTTP로 차단됐다. 사용자의 후속 수집 승인에 따라
별도 수동 보완 세대를 수집한다. 원래 실패 슬롯·세대는 수정하지 않으며 실제
늦은 HTTP 관측을 20:30 관측으로 소급 표시하지 않는다. 거래일은 자정 이후에도
2026-10-29로 고정한다. 이 실행은 정규 운영 전체 검증 완료를 뜻하지 않는다.

교차 저장소 쓰기 자격이 없는 상태에서 임의 토큰 복제나 미검증 플래그 해제를
하지 않는다. 대신 다음의 명시적 계정 독점 절차를 사용한다.

1. 장중 저장소 main의 실제 HTTP 직전 입구를 ACTIVE로 설정한다. 기존에 시작한
   runner는 취소하지 않고 자연 종료시킨다. 시간 경과로 자동 해제하지 않는다.
2. 장중 저장소 자신의 Actions 토큰으로 이전 실행의 in_progress/queued/requested/
   waiting/pending 상태를 모두 조회하고, 구 코드 실행이 없다는 영수증을 남긴다.
   새 코드의 모든 실제 OAuth/GET 경로는 동일 입구를 사용한다. 모의 전송만
   사용하는 과거 기능 회귀 테스트는 별도 합성 RELEASED 설정을 사용한다.
3. 승인된 작업자가 원래 Git 인증으로 이 비밀정보 없는 영수증을 읽어 qweasd
   제어 파일에 SHA256·main 커밋·Request ID를 고정한다. 실행 시 위조된 true
   플래그 대신 해당 영수증과 HTTP 경로 파일 해시를 검사한다.
4. qweasd는 기존 own-repository 토큰으로 실제 중앙 Git lease를 획득한다. 모든
   운영 KIS 워크플로의 로컬 concurrency도 같은 kis-validation-auth로 직렬화했다.
   활성 구 코드 중 직렬화되지 않은 실행이 있으면 새 인증을 차단한다.
5. 원래 수집기의 당일 공급자 거래일·새 마스터·적격 필터·2요청/종목·2지수·
   원천 SHA256·수급/가격 일관성·DuckDB/JSON 검증을 그대로 사용한다. 합산
   물리적 HTTP 5,600회, 1.05초, 170분 실행 창, 익일 09시 이후 신규 시작 금지를
   적용한다. 인증 실패·불명 결과는 발급 기회를 소진하고 재발급하지 않는다.
6. 만료 시각의 공급자 시간대를 추정하지 않고 모든 실제 민간 UTC offset 중
   가장 이른 만료 bound와 expires_in 중 짧은 것을 사용한다. 이 bound가 실행
   창을 안전하게 포함하지 못하면 인증 후 추가 호출 없이 중단한다.
7. 토큰을 메모리에 보유한 수집 프로세스에서 모든 파일을 유출 검사한다. 스캔
   이후 파일 변경·불명 상태는 업로드를 차단한다. 업로드 후 공식 아티팩트 ZIP을
   다시 내려받아 digest, manifest, 모든 보존 파일 해시를 검증한다. runtime의
   빈 writer.lock 파일은 원본 자료가 아니며 manifest와 업로드 양쪽에서 제외한다.
8. 장중 입구는 수집 runner의 실제 종료, 모든 HTTP 응답 종결, 중앙 소유권 해제를
   확인한 뒤 명시적으로 해제한다. 강제 종료·불명 응답이면 자동으로 해제하지 않는다.
