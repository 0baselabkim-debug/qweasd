## 적용한 실행 방식

신규 `.github/workflows/market-20261027.yml`만 사용한다. 기능 브랜치의 `.github/experiments/market-20261027.json` **단독 커밋·push 한 번**이 유한한 Job 그래프를 시작한다. main에서만 작동하는 cron을 사용하지 않는다. 기존 중단된 워크플로는 활성화하지 않는다.

`authorize → wait1 → wait2 → wait3 → master → round1 → round2 → round3 → round4 → comparison` 순서다. 후속 회차는 선행 회차가 종료될 때까지 대기한다. 선행 회차가 실패해도 마스터가 검증됐다면 다음 회차는 독립적으로 시도하며, 실패한 회차는 실패로 보존한다. 마스터 검증에 실패하면 4개 수집 Job은 모두 실행되지 않고 비교 보고서는 불완전 결과를 기록한다.

대기 Job은 10월 27일 10:00·14:00·17:30 KST를 경계로 나뉜다. 개별 Job의 GitHub 실행시간 한도를 넘지 않도록 각 대기는 4시간 30분 이내로 제한한다. 시장 인증정보는 대기 Job에 주입하지 않는다. 마지막 대기 이후 17:30 KST에 공식 마스터를 수집한다. 각 수집 Job은 의존성·설치를 준비한 뒤 자신의 지정 시각까지 기다린다.

이는 정확한 시각을 목표로 하는 일회성 예약이며, GitHub 큐·설치·앞 회차 지연 때문에 정시 시작을 보장하지 않는다. 각 회차에 예약 시각, Job 실제 시작, 수집 실제 시작과 지연 초, 최초 HTTP, 마지막 응답, 최종 검증 시각을 별도로 기록한다. 시각은 소급하지 않는다. 유효 창은 **해당 예약 시각부터 170분**이며 지연 때문에 창을 벗어나면 새 HTTP 없이 실패한다. 다른 회차로 대체하거나 창을 자동 연장하지 않는다.

`kis-validation-auth` 동시 실행 잠금을 기존 수동 KIS 실행기와 공유한다. 이 실험의 마스터·수집 Job이 동시에 인증/시장 요청을 보내지 않는다. Actions 재실행은 `GITHUB_RUN_ATTEMPT != 1`에서 차단한다. 동일 워크플로에 이전 Run이 있으면 추가 push로 재무장할 수 없다. 비교 뒤 후속 수집 Job·cron·자동 재시작은 없다. 취소는 해당 Actions Run을 취소하면 된다.

## 10월 27일 모집단 확정

10월 26일 마스터는 새 모집단으로 사용하지 않는다. 10월 27일 KST 관측 시각과 일치하는 KIS 공식 KOSPI·KOSDAQ 마스터를 새로 조회한다. KIS 휴장일 조회도 동일 거래일을 확인한다. 인증을 포함하여 이 준비 단계는 **최대 HTTP 4회**, 재시도 없이 실패 시 중단한다.

기존 master 파서의 상품군·거래정지·관리·정리매매·SPAC·우선주·상장일 필터를 유지한다. 시장별 최소 행 수(KOSPI 500, KOSDAQ 1,000), 전체 2,000 이상, 종목코드 중복, 기존 지정 종목의 이름/시장도 검증한다. 날짜가 다른 마스터를 소급해 사용하지 않는다.

새 마스터의 원문·원장·행 목록·분석 적격성·제외 사유·모집단 SHA256을 `market-20261027-master`에 고정한다. 4개 회차는 매번 이 아티팩트의 ZIP digest, manifest, 원문 SHA256, 원장과 파싱 결과를 재검증한다. 종목별 시장·대상 코드 집합과 적격 개수도 최종 검증에서 재확인한다. 고정된 파일의 모집단이 달라지면 정상 수집으로 승인하지 않는다. 비교 파일은 공통 종목·모집단 차이·누락·식별 불일치를 따로 출력한다.

회차별 정상 예상 HTTP는 `2 × 적격 종목 수 + 3`(인증 1, 지수 2), 최대 **5,600회**다. 적격 종목이 2,798개를 넘으면 이 승인 예산으로 정상 수집이 불가능하므로 HTTP 전에 차단한다. 기존 2,349개가 그대로일 경우 회차당 4,701회, 네 회차와 새 마스터를 합한 정상 예상은 18,808회다. 이는 모집단 확보 전 예상이며 실제 호출/종목 수가 아니다. 전체 최대는 `4 × 5,600 + 4 = 22,404`회다.

## 기존 수집·검증 유지

`kis_manual.run()`은 기존 알고리즘을 사용하며 새 실험에서만 날짜·세대·모집단 정책을 인자로 전달한다. 기본 호출의 10월 26일 가드와 `Providers.fetch()`의 익일 가드는 그대로다. 종목별 수급 1회·원주가 일봉 1회와 두 지수를 순차 수집하며 최소 간격 1.05초, 기존 제한적 재시도·백오프·장애 중단 정책을 유지한다.

각 세대는 별도 디렉터리·binding·원장·task/cache identity의 generation ID를 갖는다. 같은 회차 내부에서만 이미 성공한 원문을 복구에 재사용한다. 다른 회차의 시장 응답·DB·JSON을 신규 관측에 넣지 않는다. 동일한 원문 바이트가 재응답되어 SHA256이 같더라도 별도 실제 HTTP/원장/관측 시각을 갖는다.

날짜·종목코드·시장·수급/가격 종가·거래량·거래대금 일치, 기관 수량 검증, 원천 무결성, DuckDB/JSON 전체 값 비교를 유지한다. 누락된 값은 채우지 않는다. 실패/미검증 행은 전체시장 완료로 표시하지 않는다. 원천과 부분 수집 원장은 실패해도 보존·스캔·seal하며, 인증정보 스캔 실패 시 업로드를 금지한다.

각 세대 아티팩트는 원문 gzip, 관측 metadata, append-only HTTP/성공/실패 원장, 원문 기반 검증 결과, DuckDB, JSON, 고정 모집단과 master receipt, 실제 성능 수치를 포함한다. 보존 기간은 **30일**이다. 자동 비교 아티팩트는 `market-20261027-comparison`이다.

## 실제 API 필드 의미와 비교 범위

[고정한 공식 KIS 예제 출처·SHA256](market-stability-20261027-api-semantics.json)에 요청별 의미를 기록했다. KIS 공식 공개 코드 커밋 `cd63caee6aeb90553d506b15ab6866cfad23beda`에서 확인했다.

- 기존 종목 요청 `FID_COND_MRKT_DIV_CODE=J`는 **KRX 범위**다. 공식 예제는 `NX=NXT`, `UN=통합`을 구분한다. 본 실험은 기존 J를 유지하며 NX/UN 추가 요청을 하지 않는다. 따라서 NXT 거래 포함 여부나 NXT 종료의 인과적 효과는 이번 J 관측만으로 확정할 수 없다.
- 가격 `FID_ORG_ADJ_PRC=1`은 원주가다. `output2`의 `stck_bsop_date=20261027` 행에서 OHLCV/거래대금을 비교한다. `output1`의 현재가 등 문맥 필드는 별도 이름공간에 보존·비교하며 기준일에 묶인 값이라고 가정하지 않는다.
- 수급 `frgn_ntby_qty`는 주식 수량, `frgn_ntby_tr_pbmn`은 기존 검증 규칙에 따라 백만원→원으로 변환한다. 제공된 매수/매도/순매수 및 기타 원천 필드도 모두 보존한다.
- 기관 수량은 기존 검증을 유지한다. `orgn_ntby_tr_pbmn` 원문 단위가 확정되지 않았으므로 기존 `institution_net_amount=null`, `unit_unverified`를 유지하고 원문 값 자체는 비교한다.
- KOSPI·KOSDAQ 지수는 기존 U/0001·1001 요청을 사용하며 지수 변경은 종목 동일성 비율과 분리해 비교한다.

모든 HTTP 원문은 그대로 보존한다. 시장 데이터 전체 비교는 대상일 `output2`의 **모든 필드** 및 `output1` 전체 문맥 필드를 대상으로 한다. 이전 거래일의 응답 이력도 원문에 남지만, 다른 날짜의 수정이 대상일 변경으로 오인되지 않도록 대상일 동일성 계산에서는 제외한다. 핵심 비교는 대상일 OHLC/거래량/거래대금·외국인/기관 순매수와 대상일의 제공된 외국인·기관 관련 필드를 별도로 비교한다.

숫자는 Decimal 기반으로 정확히 정규화한다. `1`, `1.00` 같은 표시 차이는 같게 처리하고 식별 코드의 선행 0은 유지한다. null·빈 문자열·누락·0은 서로 다르다. 값 판정에 반올림이나 허용오차를 쓰지 않는다. 변화량과 변화율은 **정확한 분자/분모**로 JSON에 보존한다. 변화율은 `100 × (후-전)/abs(전)`이며 기준값 0이면 정의 불가다.

수집 시각·요청/generation ID·원천 해시는 시장 값 동일성에서 제외하고 메타데이터 비교에 따로 보존한다. 원문에 실제로 제공되지 않은 매수/매도 필드를 만들지 않는다.

## 자동 비교와 안정화 판단

4회차가 끝나면 성공·실패·미실행을 모두 포함해 비교 Job이 실행된다. 각 아티팩트의 ZIP·manifest·원천·원장·DB를 다시 검증한다. 검증할 수 없는 회차는 `NOT_RUN_OR_UNVERIFIABLE`과 원인으로 표시하며 성공으로 추정하지 않는다.

18→21, 21→00, 00→03, 18→03의 네 구간을 계산한다. 각 `pair-*.json`에 비교 가능 수, 전체/핵심 동일 수와 비율, 카테고리별 변경 종목, 필드별 변경 수와 정확한 변화량·변화율, 전체 변경 상세, 동일 종목 목록, 모집단 차이, 메타데이터 비교 및 지수 비교를 저장한다. 큰 절대 변화 50개와 외국인 변경 종목 목록도 포함한다.

- A: 완전한 동일 모집단과 내부 검증을 갖추고 모든 시장 필드가 동일.
- B: 핵심 필드는 동일하고 기타 필드만 변경.
- C: 일부 핵심 필드/종목 변경.
- D: 핵심 변경 종목이 비교 가능 종목의 **엄격한 과반(50% 초과)**.
- 누락·검증 실패·모집단 변경은 A/B 승인을 막고 불완전 비교로 보고.

최초 동일 구간, 마지막 변경 구간, 마지막 회차까지 무변경이 유지된 구간을 전체·핵심·가격·거래량/거래대금·외국인·기관별로 출력한다. 앞에서 같았어도 마지막 회차에서 변하면 이전 동일 구간으로 안정화를 주장하지 않는다. 완전한 4회 관측이 없거나 마지막 핵심 구간에 변경이 있으면 권고는 `현재 실험만으로 판단 불가`다.

무변경 suffix가 관측되면 해당 구간의 이른 시작 시각을 조건부 수집 시간 후보로 제시한다. 이는 00→03이 같다고 00시에 공식 확정됐다는 의미가 아니다. 권고에는 실제 회차 완료 시각, 종목별 수급/가격의 실제 관측 시각, 약 90분 이상 걸리는 순차 수집의 시간차를 함께 해석해야 한다. 운영 예약은 자동으로 만들지 않는다.

KRX 공식 대조는 이번 Job의 선행조건이 아니며, 검증된 10월 27일 동일 시장 범위의 공식 원천이 확보되지 않은 동안 **PENDING_KRX / UNVERIFIED**다. 공식 정확성과 시간대별 동일성은 별개다. NX/UN 관측이나 공식 대조는 별도의 검증 단계가 필요하다.
