# V2와 고정 전체시장 원문 연결

실제 실행 결과는 [연결 검증 보고서](../reports/decision-evidence-v2-connected/RESULT.md)에 기록한다. 기존 게시본용 입력은 유지하며, 새 어댑터를 명시적으로 선택한다. 수집/인증/예약/게시 코드는 바꾸지 않는다.

현재 어댑터의 신뢰 앵커는 Run40882669831 / Artifact12910068161 / 거래일2026-10-29 / ZIP SHA256 `4682801c9d88a5fb43496c55263e66402aef42f089f8987d667458d15cf8e8c7`이다. manifest도 별도 영수증 SHA256으로 고정한다. 다른 세대를 같은 데이터로 취급하는 범용 자동 입력기는 아니다.

## 읽기와 출력

실행 환경에서 `collector_artifact.extract`가 공식 ZIP의 해시·manifest·파일 집합·모든 파일 해시·경로/용량을 검증하고 새로운 독립 디렉터리에만 압축을 푼다. `verify_directory`가 압축 해제 뒤의 파일 변조도 검출한다. `collector_source.load`는 기존 수집기의 읽기 전용 검증을 재사용하고, 같은 세대의 원문·마스터·원장·원본 DuckDB/JSON을 다시 대조한다.

```bash
python scripts/build_decision_evidence.py \
  --source-kind collector-artifact \
  --snapshot /독립/압축해제/원문 \
  --reference-directory snapshot/decision-support \
  --out /독립/V2출력
```

위 명령은 개발자용 재현 인터페이스다. 이번 작업에서는 공식 Actions에서 직접 실행했다. 사용자에게 원문 이동이나 코딩을 요구하지 않는다. 직접 다운로드가 차단된 클라우드에서 인증/프록시를 우회하지 않는다.

과거 `snapshot/decision-support`에서 가져오는 것은 날짜·시장·종목이 같은 보존 KRX **공식 대조 원문**뿐이다. 게시된 가격·외국인/기관 수급·기존 후보·재무·매크로·업종을 최신 분석 입력에 가져오지 않는다. 원본 세대·참조 파일 트리 해시는 별도로 identity에 묶고 읽기 전후 불변을 검사한다.

수급30일과 원주가 최대40거래일을 파싱한다. J/KRX와 원주가1, 종목코드/일자/요청 범위/중복·미래 날짜를 검증한다. 달력은 해당 세대의 KIS U 지수 응답이며 KRX 공식 달력이라고 부르지 않는다. 수급1/3/5/20일, 기관 수량, 가격 지표 등 기존 V2 함수를 재사용한다.

외국인 금액은 기존 공급자 백만원 단위를 KRW로 정규화한다. 매수/매도 수량 항등식과 같은 날짜 close/volume/turnover를 검증한다. 기존 백만원 단위 금액 항등식의 ±1 공급자 단위 규칙을 그대로 사용하며 가격 허용오차로 전용하지 않는다. 기관 금액은 미확인 단위이므로 null이다.

가격은 기존 `accept_chart`의 공식6필드 정확 일치·기업행사·무거래·날짜 검증을 유지한다. 조정 이벤트 이전 이력을 무검증 연결하지 않는다. 최신 공식 원문이 없으면 approved 가격·SMA·ATR·상대강도·가격 태그는 unavailable이다. 원시 잠정 가격은 원본ZIP에 보존한다. 수급만 있어도 투자 후보20개를 억지로 만들지 않는다.

## 재검증과 인과 해석

과거 관측값을 바꾸지 않고, 동일10월23일·동일 공통 종목의 나중 원주가와 KRX를 별도 비교한다. 당시의 데이터가 나중 값이었다고 소급하지 않으며 historical_backtest_eligible=false를 유지한다.

나중 원주가가 KRX와 같다는 사실만으로 모든 충돌 원인을 공급자 수정이나 수정주가라고 단정하지 않는다. 이전 원주가/수정주가 쌍과 동일 시장·동일 날짜를 확인할 수 있는 경우에만 원주가 빈티지 변경을 입증한 것으로 분류한다. 확정 시각이나 공급자 내부 처리 원인은 별도 미확인이다. 응답 조정 플래그는 미확정 이력 차단 근거이며 특정 분할/배당락 사건을 추정하는 근거로 사용하지 않는다.

최신10월29일 검증 상태와 과거10월23일 재검증 성과를 각각 보고한다. 다른 날짜/모집단끼리 '승인 종목 수가 늘었다'고 계산하지 않는다. 전체 비교 상세와 원천 해시는 독립 아티팩트에 저장한다.

## 유한 Actions 경로

`.github/workflows/decision-v2-source-20261029.yml`은 `feat/decision-evidence-v2`의 전용 제어 JSON 변경만 받는다. 정기 cron이 없고 `kis-validation-auth` 잠금이나 운영 Secrets를 사용하지 않는다. request_id·원본 run/아티팩트/hash·시간창·실행1회차·저장소/브랜치를 검증한다. 제어 파일의 검사/분석은 시장 API 요청0회다.

결과는 별도 `evidence/decision-v2-source-20261029` 브랜치에 요청별 새 파일로 기록한다. source 원장이나 공유 계정 상태 브랜치가 아니다. 원본ZIP과 DB/JSON/Parquet·manifest·원인 분석은90일 아티팩트에 별도 보존한다. 업로드 직후 다시 공식 다운로드하여 실제 저장 ZIP과 전 파일을 검증한다. Job 성공/아티팩트 존재만으로 데이터 검증을 대신하지 않는다.

사용자가 요청한 draft PR 생성만 별도 `pr` 모드에서 수행한다. 이에 필요한 최소 `pull-requests:write`는 이 새 workflow에만 적용했다. 기존 운영 workflow 권한·repo 설정·Secrets는 바꾸지 않는다. main 병합이나 PR 승인/자동 배포 기능은 없다.

## 보류와 후속 조건

10/26~29 두 시장 KRX8개 날짜/시장 조합이 추가 필요하다. 기존 journal의 bootstrap·일별 클래스·미해소 예약과18~23시 가드를 실제로 검토했다. 읽기 전용 검증 workflow는 KRX 키도 받지 않고 요청을 전송하지 않는다. 새 root로 예산을 초기화하거나 시간 가드를 우회하지 않는다. 향후 조회는 허용 시간에 원장/예약을 다시 확인하고 기존 허용 클래스에서 영속 예약한 뒤 수행해야 한다. 이번 작업은 실제 조회 예약을 등록하지 않았다.

원본의60달력일 요청에서 최대40거래일만 확보됐으므로 SMA60/120은 현재 원문만으로 복구할 수 없다. 공식 KIS 명세의1회 최대100행도 고려해야 한다. 기존 수집 매개변수·종목당 요청 수를 이 작업에서 바꾸지 않고, 이미 검증된 연속 이력의 명시적 연결 또는 별도 승인된 장기 확보를 후속 조건으로 둔다.
