## 2. 2,162개를 모두 ‘정상 수정주가 차이’로 해석하면 안 되는 이유

기존 `raw_adjusted_conflict_unresolved`는 명칭과 달리 두 종류를 함께 세었다.

1. 수급 API의 공란 옵션 가격과 나중 수정주가 관측의 차이.
2. 가격 차트 API의 **명시적 원주가(1)·수정주가(0)** 응답 차이.

보존된 KIS 공식 예제에서 차트의 `0=수정주가`, `1=원주가`는 확인된다.

공란을 차트 API의 `1`과 동일한 의미로 단정할 근거는 없다. 두 API 모두 요청 시장은
`J`였고, 공식 예제는 J=KRX, NX=NXT, UN=통합으로 구분한다.

이번에는 관측 차이 유형을 별도 CSV로 분리했다. 아래는 **중복 제거한 배타적 집계**다.

## 4. 정상적인 수정주가 차이의 과잉 차단 검사

현재 연결 로직은 조정이 입증되지 않은 상태에서 원주가와 수정주가의 직접 불일치를 차단한다.
기업행사가 공식적으로 증명되고 조정계수·적용일·가격/거래량 정밀도까지 검증된 종목이라면
단순 동일값 비교를 계속 요구하는 것은 부적절할 수 있다. 하지만 현재 최신 40일 범위에서
명시적 차이가 확인된 **51개**를 정상 조정이라고 일괄 승인할 자료는 없다.

`explicit-adjustment-differences.csv`에 날짜별 옵션 0/1 원본 해시, 관측 시각, 조정 표시,
종가 비율을 보존했다. 가격이 비례해 보인다는 관찰만으로 공식 조정계수를 만들지 않았다.

상지건설(042940)은 예외적으로 기존 공식 자료에서 **2026-09-22 유상증자 권리락,
기준가격 5,680원**이 확인돼 있다. 따라서 기업행사 자체를 ‘미확인’이라고 되돌리지 않았다.
다만 기존 KIS 원종가 5,900원의 해당 날짜 KRX 대조와 공급자의 정밀도 규칙은 부족하다.
기존 연구의 가격 312필드가 관찰상의 내림 계산과 맞더라도, 거래량 3개 날짜에서 1주 차이가
남아 공식 규칙을 대신할 수 없다. 보류 사유는 **사건 미확인**이 아니라 **조정 검증 미완료**다.

이번 수정은 가격 동일성·연속성·기업행사 검사를 제거하지 않는다.
향후 조정 검증 경로는 원가격을 공식 KRX와 대조하고, 공식 기업행사 근거 및 공급자 조정 규칙으로
별도 전체 가격열을 검증해야 한다. 일부 종가를 바꾸거나 10/20 검증으로 과거 전체를 해제하면 안 된다.

## 6. 연결 통과 227개 중 스냅샷 불일치 31개

31개 모두 10/19의 **adjusted_close는 일치**, **volume·turnover는 이전 값**이었다.
31개 모두 새 값의 거래량·거래대금이 기존보다 크며, 기존 값은 10/19 수집 체크포인트와 같다.
새 가격열의 OHLCV 6개는 공식 KRX 응답과 모두 일치한다.

`screener/daily.py`는 당시 원종가·거래량·거래대금을 보존하고, 후속 일일 수집에서는
과거 `adjusted_close`만 갱신한다. 이 설계로 **가격열과 거래량열의 관측 버전이 분리**된 것이
연구 연결 검사에 걸린 직접 원인이다. 공급자가 최초 수치와 다른 값을 반환한 배경까지
이 코드 분석으로 입증되는 것은 아니다.

예: BYC(001460), 10/19 종가 37,000원은 동일. 기존 거래량 **2,374주**,
거래대금 **86,900,400원** → 공식 대조 후보 **2,375주**, **86,938,000원**.

`research_snapshot_view()`는 다음을 모두 만족할 때만 별도 메모리 비교값을 만든다.

1. 이미 40일 연결 검증을 통과한 동일 종목·날짜이며 현재일이 아닌 과거 날짜.
2. 기존 수정종가는 그대로 같고, 기존 원종가·거래량·거래대금은 원 체크포인트에서 재현됨.
3. 해당 날짜·시장 공식 응답의 유일한 값이 후보 OHLCV **6필드 전체**와 같음.
4. 다른 보존 공식 버전과 상충하지 않음.

기존 DB와 원종가는 수정하지 않는다. 원본/후보/공식 해시·조회 시각을 `research-overlays.json`에
함께 저장했다. 부분 근거 실패 시 비교 통과로 표시하지 않는다.
**이 메모리 대조층은 연구 분류용이며 기존 실시간 신호 등록의 엄격한 스냅샷 검사를 우회하지 않는다.**

## 7. 부족했던 50개의 원본 수급 복원

이전 검색은 `former-observations-market.tar.xz`와 최신 체크포인트만 봤다.
이번에는 history/observations/candidates/pending 등 보존 버전을 모두 확인하고,
`staging/kis_history_20261014.json.gz`, `research/daily-replay.json.gz`도 재사용했다.

- 기존 196개 중 부족 50개 **전부** 원본 필드를 찾았다.
- 기존 연결 227개 전체 기준으로는 부족 75개가 복원되어 **227개 모두 20일 재현**된다.
- 관측 이력 탐색만 확대해도 기존 부족 50개 중 12개를 찾았고, 나머지는 본 수집 파일에서 찾았다.
- 본 수집은 `metric/received_at_utc`, 시범 수집은 `history_metric/history_request_date` 형식이었다.
  두 형식을 섞어 하나만 허용하면 정상 보존 자료도 누락으로 오판한다. 보존된 수집 코드의
  실제 계약에 맞춰 각각 검증했다.
- 본 수집 파일은 전체 HTTP 원문이 아니라 **실제 응답에서 저장한 필드 묶음**이다.
  이를 전체 HTTP 원문이라고 표현하지 않는다. 파일/아카이브 멤버 해시와 모든 사용 필드를 대조한다.
- 같은 날짜에 다른 순매수 금액이나 수량의 버전이 있으면 DB에 맞는 것만 골라 통과시키지 않는다.
- 실제 0과 음수는 그대로 보존하고 없는 날짜를 만들지 않는다.
- 관측 시각이 없는 옛 시범 응답은 실제 조사 시각을 지식 상한으로 사용하게 되어 있다.
  이번 최종 선택된 227개 묶음에는 그런 시각 미상 원문이 필요하지 않았다.

금액 및 원문에 존재하는 수량의 독립 SQL 대조 건수는 `SUMMARY.json`에 기록된다.
각 종목의 20개 날짜·원문 출처·결측/충돌 판정은 `flow-restoration.csv`와 `flow-evidence/` 참조.

## 8. 실제 신규 신호 전까지 남은 최소 조치

**현재 등록 가능 0개**를 유지한다. 40일 연결/수급 재현 통과는 공식 최종 확정이나
다음 개장 전 신호 고정 완료와 같지 않다.

1. 공식 KRX **10/16 양 시장** 자료로 관측 차이 2,159개와 별도 보류 37개를 대조한다.
2. 최신 신호 기준일의 **KRX 양 시장** OHLCV 검증 자료를 확보한다. 현재 보존본에는 10/20이 없다.
3. KIS 공식 휴장일 응답 원문에서 다음 거래일·개장일과 중간 휴장일을 확인한다.
4. 다음 유효 기준일 데이터에서 연구용 날짜별 대조 근거를 전향 등록 경로까지 통합 검증한다.
   현재 실제 등록 경로의 스냅샷 충돌 차단은 그대로이므로, 31개는 연구 비교 해소만 완료한 상태다.
5. 공식 다음 개장 **이전** 실제 시각에 데이터 해시·조건·후보를 고정한다.
   이미 시한이 지난 기준일을 소급 등록하지 않는다. 조건 충족 0개와 자료 부족을 분리한다.

API 최소 계획 및 종목 목록은 [API_PLAN.md](API_PLAN.md), `official-price-targets.csv`에 있다.
승인 전 실행하지 않았다. 과거 가격 충돌이 해소되지 않아도 별도로 검증된 정상 종목은 독립적으로
다음 신호 시험을 진행할 수 있다. 단, 수익률·MAE·MDD 결과는 아직 생성하지 않는다.
