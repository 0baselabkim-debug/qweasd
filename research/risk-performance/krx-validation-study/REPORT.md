# KRX 기반 연구용 가격 검증 — 구현 및 보존 자료 시험

이번 작업은 **연구용 구현·오프라인 검증 완료, 실제 10/22 검증·자동 운영은 미실행**이다. 신규 시장 API 0회, 신규 예약 0개, 실제 신호 등록 0건이다. 운영 main/DB/JSON/대시보드/워크플로 및 A·B·C·D 규칙을 변경하지 않았다.

## 실제 데이터 결과

고정 모집단 2,429개, 기준일 **2026-10-20**. 최초 10/20 체크포인트, 10/21 정기 수집에 보존된 10/20 이력, 기존 공식 KRX 응답을 사용했다. 10/22 당일 스냅샷을 검증한 결과가 아니다.

- 알파칩스(117670): 후속 종가 6,950원 vs 공식 13,900원, 후속 거래량 479,420주 vs 공식 239,710주. 거래대금 3,320,161,870원은 같다. 비율 관계만으로 분할·기업행사라고 확정하지 않고 가격 충돌로 보류했다.

- 보류 52개 = 조정 검증 51개 + 알파칩스 1개. 후속 파일만 보면 부재 1개를 포함해 53개이며, 두 통계를 혼합하지 않는다.

## 공식 40일 구성의 현재 한계

추가 조사한 보존 공식 일괄 응답은 **10/14·10/15·10/16·10/19·10/20**다. 종목별 유효 공식 가격은 5일 2,423개, 4일 3개, 3일 1개, 1일 2개다. 따라서 전 종목에 공식 40일 이력이 부족하다.

기존 KIS 기반 60~94일 자료와 189개 연결 통과 연구는 그대로 보존한다. 이는 ‘40일 모든 날짜를 공식 KRX로 대조한 별도 경로’와 기준이 다르며, 기존 189개 판정을 0개로 변경한 것이 아니다. 이번에는 부족한 공식 날짜를 KIS 숫자로 채우거나 다른 버전의 종가만 조합하지 않았다.

## 구현 구조

1. `krx_validation.py`: 원본 bytes를 SHA-256 주소로 보존하고, 파생 관측·판정·오류를 별도 불변 파일로 저장한다. 최초/후속 KIS와 공식 응답은 각각 보존한다. 파일 시스템 자체의 WORM 보장은 아니며 해시·Git 이력으로 변경을 탐지한다.
2. 날짜·시장·종목·시각·원본 해시·6필드를 검증한다. 결측을 0으로 만들지 않고 원 단위·주 단위 정수로 정확히 비교한다. 한 원이라도 다르면 차이를 기록한다.
3. 공식 응답 여러 버전이 서로 다르면 `official_version_conflict`로 보류한다. 가장 늦은 응답을 무조건 채택하지 않는다.
4. `official_context`: 동일 KRX 원시세 기준의 **전체 일봉**으로만 40일을 구성한다. 날짜별 출처·관측 시각을 보존하고 연속된 이전 문맥도 유지한다. KIS 종가를 공식 거래량 행에 끼워 넣지 않는다.
5. `review_adjustment`: 공식 문서 원본 해시·인용문·명시적 필드별 계수·반올림 규칙을 검증하고 산술을 대조한다. 문구의 의미와 행사 적용 구간에 대한 독립 검토가 남으면 자동 해제하지 않는다. 실제 검증 가능한 새 기업행사 증거는 확보하지 않았고 51개를 계속 보류한다.
6. `prepare_snapshot`/`prepare_signal`: 게시본 무결성, 공식 40일 근거, 공식 거래일 원본, 기존 수급 재현·수용 기준, 실제 시각의 다음 개장 전 조건을 확인한다. 기존 `build_signal`/`cohort`/스윙 규칙을 재사용한다. 결과는 `prospective_preparation`, `pit_eligible=false`인 **준비 자료**이며 실제 신호 저장은 하지 않는다.
7. 게시본 오류는 별도 오류 저장소에만 기록한다. 기존 신호 저장소를 열거나 수정하지 않는다. 읽는 도중 게시본이 달라져도 준비 결과를 통과시키지 않는다.

## 실행 및 성능

마지막 오프라인 시험 **18.005초**. 실제 응답 6필드 대조, 2,429개 종목 분류, 원본 보존·해시 확인을 포함하며 시장 API는 호출하지 않았다. 40일이 부족하여 실제 신호 등록까지 걸리는 시간을 측정한 것은 아니다.

|향후 작업|예상 시장 API|시간의 근거와 한계|
|---|---:|---|
|신규 거래일 KRX 일괄 검증|KOSPI 1 + KOSDAQ 1 = 2회; KIS 가격 0회|이전 실제 KRX 요청 1.18~2.02초/회, 이번 오프라인 약 18초. 대기·보존 포함 1~2분 설계 예상, 미실측|
|현재 40일 구간의 누락 날짜 보완|35거래일 × 2시장 = **70회** 기본량|과거 응답이 동일 범위로 제공된다는 전제. 호출 간격·실패·검증 포함 5~15분의 초기 예상, 미실측·미승인|
|새 거래일 달력 확인|현재 보존 응답으로 10/23 개장일 확인 가능, 추가 0회|범위가 끝나거나 개장시각 예외가 있으면 별도 공식 근거 필요|
|기존 관측·해시·수급 재현|0회|보존 자료만 사용|

70회는 부족한 날짜를 채우는 기본량이며 51개 기업행사·기존 공식 응답 충돌·종목 누락까지 모두 해결한다는 뜻이 아니다. 10/22 이후에는 해당 40일 구간으로 부족 날짜를 다시 계산한다. 실제 조회·실패 재시도는 별도 승인 없이는 하지 않는다.

## 아직 남은 작업

- 누락 공식 가격 이력 확보 승인 및 실제 제공 범위 검증. 대안은 새 날짜 공식 자료가 40일 쌓일 때까지 연구 준비 상태 유지.
- 기업행사·조정계수·거래량/거래대금 조정 방식의 공식 근거와 독립 검토. 알파칩스의 비율 차이 원인도 미확정.
- 10/22 정상 게시본과 해당 날짜 KRX 응답을 확보한 뒤, 별도 승인된 **수동 검증**. 절차는 [MANUAL_RUNBOOK.md](MANUAL_RUNBOOK.md).
- 실제 전향 등록은 별도 승인 후 기존 불변 저장/중복 방지 경로에 공식 문맥 해시를 함께 연결해야 한다. 현재 코드는 준비 상태까지이며 실제 등록은 활성화하지 않았다.
- 기존 개장 전 게이트의 일반 거래일 09:00 기준을 유지했다. 특별 개장시각이 적용되면 공식 근거 없이는 적용하지 않는다.
- 자동화/정기 일정 연결은 이번 범위에 포함하지 않았다. 향후에도 운영 게시가 연구 실패에 의해 막히지 않도록 분리해야 한다.

## 재현

```sh
python research/risk-performance/krx_validation_trial.py
python -m pytest -q research/risk-performance/tests/test_krx_validation.py
python -m pytest -q
```

첫 명령은 네트워크를 차단하고 **보존된 10/20 자료만** 읽는다. 10/22를 지정하는 인수나 실제 등록 옵션이 없다. 실행별 결과는 콘텐츠 해시 디렉터리에 보존하며 이전 실행을 덮어쓰지 않는다. `CURRENT_RUN.json`이 최종 코드 결과를 가리킨다. 테스트용 가상 시세는 테스트의 임시 디렉터리에만 존재한다.
