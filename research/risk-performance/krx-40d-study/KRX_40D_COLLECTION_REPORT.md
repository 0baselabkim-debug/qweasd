## 재사용·최소 조회량

기존 해시 주소형 공식 보관본과 최신 main의 reference/reference-observations 118파일을 읽었다. 모든 공식 버전을 함께 인덱싱하며 새 버전을 임의 우선하지 않았다. 이번 준비 결과 신규로 필요한 공식 시장·거래일은 **70개(각 시장 35일)**다.

- 요청 목록: `plans/b5568b15ed2b0dea992651657cba886cc2d32c558e2a8bad60a84b9ea960158c.json`.
- 기존 성공 조합 재조회 없음. KIS 시세·수급·인증 요청 0, KRX API 키 방식은 별도 인증 요청 없음.
- 배치 계획: 20+20+20+10, 총 70회. 실패도 80회에 포함, 여유 10회는 재조회 성공을 보장하는 예약이 아니다.
- 야간 실행 직전에 최신 main·게시 검증·달력·누락 목록을 다시 확인한다. 10/22 게시 여부를 지금의 계획으로 단정하지 않는다.

## 구현과 안전 장치

`krx40_collect.py`: 배치 최대 20, 전체 80을 프로세스·날짜·재실행과 무관하게 같은 승인 원장으로 계수. 파일 잠금·순서/이전 해시를 가진 append-only 요청 원장. HTTP 전 원격 연구 체크포인트 영속화 실패 시 요청 중단. 성공 응답은 원문 압축 바이트·원문 SHA·압축 SHA로 즉시 보존. 불명확하게 중단된 시도는 자동 재조회하지 않고 보류한다.

1.05초 최소 시작 간격, 자동 리다이렉트/재시도 없음. 401/403/429는 배치 중단 및 재개 차단. 기타 실패는 명시적인 `--retry-failed` 재개 때만 추가 예산으로 재시도. 요청 파라미터·HTTP 상태·날짜/시장 검증·시간·원본 해시·오류 유형을 기록하며 키/헤더는 기록하지 않는다.

23:00~09:00 및 운영 작업 상태를 요청마다 재검사. 기존 `kis-validation-auth` 공통 동시실행 그룹의 **수동 연구 Actions 실행임을 확인**해야 실조회 가능하다. 공유 잠금이 없는 로컬 실행은 거부한다. 실행 도중 main 버전 변경, 다른 대기/실행 작업 발생, 예산 부족이면 중단한다.

`krx40_study.py`: 정상 게시본 읽기 전용 고정 → 보존 공식 인덱스·달력 원본 해시 재현 → 누락 계획 → 공식 원시세 전체 일봉 문맥 → 수급 금액·수량 원본 대조 → 기존 classify_link 재사용. 기업행사·알파칩스·스냅샷 충돌·필요한 이전 스윙 문맥 미검증은 계속 보류. 종가만 바꾸지 않는다.

## 남은 실행과 한계

- 이번에는 야간 조회를 시작하지 않았으므로 70회 성공·공식 40일 완성·A/B/C/D 후보 수는 **아직 검증하지 않았다**.
- 현재 수집기는 수동 연구 러너의 공유 잠금을 요구한다. 기존 2종목 KIS probe를 그대로 실행하면 이 KRX 수집이 시작되지 않는다. 다음 야간 작업 시 **연구 브랜치의 수동 실행 진입점만** 연결해야 한다. 이번에는 워크플로 파일과 기존 예약을 전혀 바꾸지 않았다.
- 40일 원가격 확보만으로 과거 60~94일 스윙 문맥·조정 검증·기업행사 검증이 자동 해결되지 않는다. 기존 문맥이 판정에 필요하면 별도 보류한다. 관련 추가 요청은 80회 잔여와 사용자 승인 범위 내에서 재평가해야 한다.
- `prepare_snapshot`/`build_signal` 및 수용 검사를 통과한 묶음으로 준비 검사하는 후속 단계가 남아 있다. 이번에는 가격 문맥부터 부족하므로 그 단계를 실제 통과했다고 보고하지 않는다. 신호 저장 호출은 구현 경로에 없다.
- 실제 수집 소요 시간은 미측정. 이번 전체 오프라인 대조 **51.444초**. API 최소 시작 간격만 계산하면 70회는 최소 72.45초이고, 기존 KRX 응답 관측 시간 1.18~2.02초를 참고하면 HTTP 자체는 약 83~141초이나 이번 호출 실측이 아니다. 원장 원격 저장·운영 상태 조회·4회 재개 검증 시간이 별도로 추가되므로 실제 야간 로그로 확정한다.
