## 가격 충돌과 보류 근거

- 중복 수정주가 OHLCV 6필드 충돌: **23종목**.
- 원주가·수정주가와 중복 관측을 합친 미해소 충돌: **2,163종목**. 이 중 원주가/수정주가 차이가 미해소인 종목은 **2,162개**다. 수치는 겹치므로 합산하지 않는다.
- 현재 모집단의 10/16 관측 차이는 **2,159종목**에 있다. 기존 37종목은 과거 성과 표본에서 확인했던 부분집합이었다. 전수 대조를 하면서 범위가 확인됐으며 이전 조사 결과를 덮어쓰지 않았다.
- 같은 날짜 공식 KRX가 유일하게 후보의 6필드와 일치하는 과거 관측 차이는 별도의 `official_resolved` 감사 행에 기록했다. 원본 관측은 그대로 보존했다.
- 공식 KRX 근거가 없는 10/16, 조정가격·기업행사 근거 미확인, 거래량/거래대금 0, 신규상장·이력 부족 등은 보류했다. 분할·NXT 차이·갱신 지연 중 하나라고 추정하지 않았다.
- **기존 37종목은 모두 별도 격리 유지**. 이 목록 때문에 다른 종목이 일괄 차단되지 않는 테스트도 통과했다. 다른 종목에서 새로 발견한 실제 불일치는 해당 종목의 별도 근거로 차단한다.
- 이전 10/19 모집단과 현재 모집단은 개수가 같아도 구성은 다르다. 새로 나타난 2개 종목을 과거 이력이 있는 것처럼 취급하지 않았다.

`observation-comparison.csv`에는 날짜별 원본·후속 관측의 6필드와 공식 해소 여부를 남겼다. `all-stocks.csv`는 2,429개 고유 코드를 빠짐없이 포함하며 보류와 조건 미충족을 구분한다.

## 다음 공식 개장일과 추가 호출 필요량 — 미실행

보존 공식 지수 거래일 원문은 10/19까지, 최신 체크포인트의 휴장일 결과는 **10/20 한 행**뿐이다. 이미 처리한 휴장일 API의 전체 응답은 남아 있지 않아 다음 개장일을 확인할 수 없다. 평일을 공식 개장일로 추정하지 않았다.

공식 KIS 예제 근거: [국내휴장일조회 CTCA0903R](https://github.com/koreainvestment/open-trading-api/blob/main/examples_llm/domestic_stock/chk_holiday/chk_holiday.py). 보존 문서 해시는 `research/full-market/docs/holiday-source.json`에 있다. `opnd_yn`·`tr_day_yn`과 다음 개장일까지 중간 날짜를 확인해야 하며, 공식 예제는 **가급적 하루 1회**를 요청한다.

| 추후 필요한 확인 | 최소 예상 호출 | 조건 |
|---|---:|---|
| KIS 다음 공식 개장일 | 1회 | 기존 유효 토큰 재사용 시 인증 0회; 없으면 인증 1회 추가. 추가 페이지 필요 여부는 응답 확인 후 판단 |
| KRX 10/16 양 시장 일별 시세 | 2회 | 37종목 및 확대된 해당 날짜 충돌 검증. 접근 성공·자료 제공은 보장하지 않음 |
| KRX 최신 기준일 양 시장 일별 시세 | 2회 | 현재는 10/20. 다음 유효 연구일에는 해당 날짜 자료가 필요 |

위 첫 세 항목은 최소 **시장 조회 5회 + 인증 최대 1회**이며, 재시도·추가 페이지는 포함하지 않았다. 모두 **승인 필요 / 이번 실행 0회**다. 시장별 배치 조회이므로 KRX를 종목별로 수천 번 호출할 필요는 없다. 실제 소요시간은 미측정이며 응답 지연·403·미게시 가능성을 포함해 별도 제한이 필요하다. 달력만 해결해도 가격·수급 검증이 자동으로 통과하는 것은 아니다.

## 구현 및 수동 등록 경로

- `price_link.py`: 날짜·상장일·시장·종목·OHLCV·중복·조정 플래그·보존 원주가·공식 참조 검증. 기존 값을 덮어쓰지 않고 별도 연결 관측을 생성.
- `link_trial.py`: 해시가 고정된 실제 입력으로 2,429종목 수동 재현. 네트워크 차단 상태에서 실행.
- `make_forward_bundle` / `stage_bundle`: 공식 당일 KRX와 **원문에 실제 존재하는 수급 20행**을 기존 `daily_accepted` 규칙으로 검사하여 기존 `forward_system.py`가 읽는 묶음으로 전달. 원문 파일·아카이브 구성원 해시와 수급 행 원문 일치까지 확인. UNVERIFIED를 VERIFIED로 바꾸지 않는다.
- 실제 가격 연결 통과 227개로 준비 검사를 실행했고 **227개 모두 최신 공식 KRX 근거 미확보로 정상 거절**됐다. 성공 경로는 격리된 테스트 자료로만 확인했다.
- 신호 등록은 기존 실제 시스템 시각·다음 공식 개장 전 제한·불변 저장·중복 패턴·해시 검증을 그대로 사용한다. 날짜를 소급하는 CLI 옵션은 없다.
- 연구 저장소의 변경 방지는 애플리케이션의 덮어쓰기 금지 및 해시/Git 이력이다. 물리적 WORM 보장은 아니다.

재현:

```sh
python research/risk-performance/link_trial.py
python -m pytest research/risk-performance/tests -q
```

다음 **유효한 새 게시일**에 근거가 모두 준비됐을 때만 사용되는 수동 연결 절차(이번에는 실행하지 않음):

```sh
python research/risk-performance/price_link.py \
  --link 연구용_연결관측.json --snapshot 검증된_게시본_사본 \
  --raw-flow 원문수급근거.json.gz --reference 공식_KRX_원문.json \
  --output research/risk-performance/price-link-study/새버전-bundles
python research/risk-performance/forward_system.py \
  --snapshot 검증된_게시본_사본 \
  --bundles research/risk-performance/price-link-study/새버전-bundles \
  --calendar 다음개장일_공식근거.json
```

기존 다음 개장 전 시한이 지난 10/20 신호는 이후 자료가 보강돼도 등록하지 않는다. 다음 거래일의 실제 등록 시험은 아직 실행하지 않았으며 새 예약도 없다.

## 검증과 남은 장애물

연구 테스트 및 전체 회귀 결과는 `validation/`에 저장한다. 실제 CSV 반복 재현, 원본 해시 불변, 연결 관측 중복 미생성, 37종목 독립 격리, 가격·수급 원문 불일치 차단, 정상 자료의 조건 미충족 구분, 이전 구조 확인일 보존, 시한 경과 등록 거절을 검사했다. 테스트의 가상 달력/가격은 실제 결과 파일과 분리했다.

자동화 전 필요한 것은 최신 공식 KRX 증거, 다음 개장일 근거, 부족한 원문 수급, 남은 가격·기업행사 충돌 해소 및 **새 유효 거래일의 실제 등록·후속 관측 시험**이다. 현재 소수 연구군의 존재를 전략 성과나 실제 등록 성공으로 해석하지 않는다. 운영 시스템과 수집 일정은 그대로 유지한다.

독립 대조 결과: 연결 227종목의 전체 보존 가격 및 신규 일봉을 원본과 재대조했고, DuckDB 수급 합계 **681개(종목당 5일·개선액·20일)**가 일치했다. 비밀정보 필드 검출 0개, 과거 가격 덮어쓰기 0개, 37종목의 연결 정상군 편입 0개였다. 최종 수동 전수 재검증은 **23.10초**였으며 시장 API 대기 시간이 없는 보존 자료 계산 실측이다.

로컬 전체 회귀 **369개 통과(259.87초)**, 최종 연구 테스트 **61개 통과(2.50초)**. 연구 테스트는 전체 회귀의 부분집합이므로 합산하지 않는다. 최종 코드 커밋의 CI 결과는 별도 검증 기록에 남긴다.

현재 활성 연결 자료는 CSV의 `link_sha256`가 가리키는 **research-linked-40-v2** 관측 227개다. 개발 중 생성된 이전 관측도 감사 이력으로 보존했으므로 저장 파일 개수를 종목 수로 세면 안 된다. v1 관측은 등록 준비 함수에서 재검증 요구로 차단한다.
