# 2026-10-19 전체 종목 1차 전수 선별 (연구 전용)

운영 적용·수익률 검증·백테스트가 아니다. 고정 2,429종목과 동결된 10/19 수급을
사용하고, 사후 조회 가격의 실제 관측 시각을 별도 보존한다. main으로 병합하지 않는다.

- 브랜치: `research/full-market-transition-20261019`
- `prepare.py`: 기존 보존 자료 검사 및 필요한 요청만 선별(시세 호출 없음)
- `collect_batch.py`: 수동 300회/배치, 총 3,800회, 물리 호출·인증·재시도 포함
- `collect_calendar.py`: 같은 요청 예산 안에서 두 시장 공식 지수의 거래일 응답을 별도 검증
- `analyze.py`: 오프라인 원본 대조·단계별 사건/현재 상태·후보 분류
- `stages.py`, `strategy.py`: 선행 연구와 바이트 단위 동일, `rule-hashes.json` 참고
- `inputs/`: 동결 운영 자료의 연구용 사본·선행 결과. 실제 원본만 포함
- `collection/`: 내용 해시별 새 관측, 배치별 물리 요청 기록, 재개 체크포인트
- `results/`: 전수 CSV, 후보·보류 자료, 연구 전용 DuckDB/Parquet, 보고서
- `tests/`: 가상 시험 자료는 임시 디렉터리에서만 사용하며 결과 DB에 섞지 않음

재현(추가 API 호출 없음): 저장소 루트에서

```sh
python -m pip install -r research/full-market/requirements.txt
PYTHONPATH=research/full-market python -m pytest -q research/full-market/tests
python research/full-market/analyze.py
python research/full-market/verify.py
python research/full-market/write_report.py
```

`prepare.py`는 큰 감사 보관소를 다시 검사하는 선택 단계이다. 기존 조사된 과거
스냅샷 31개 목록은 선행 연구 조사 결과를 보존한 것으로, 새로 31개를 수집했다는 뜻이 아니다.
기존 원본의 내용 해시는 다시 확인했다. `collect_batch.py`는 로컬에서 실행하지 않는다.

새 예약은 없다. 연구 브랜치의 기존 **수동 진단** 워크플로 파일만 연구 실행에
사용한다. main의 해당 파일·정규 수집/게시 워크플로·cron·KIS 운영 코드는 그대로다.
인증정보는 기존 GitHub Secrets에서 읽으며 결과 파일에 포함하지 않는다.

## 사건과 현재 상태

사건은 원래 전후 2일 엄격 스윙·40거래일 규칙으로만 생성한다. 동률은 극값에서
제외하며, 동일 종류 연속 극값은 더 극단적인 값(동률이면 앞선 값)을 사용한다.
확인일 이후 가격으로 과거 사건을 바꾸지 않는다. 동일 L2/L3의 반복 확정 돌파는
첫 사건만 기록한다. 데이터 관측 시각이 사건일보다 늦으면 사후 재구성이라고 표시한다.

현재 상태는 최근 40일에 포함된 가장 최근 유효 L2의 구조를 표시한다. L2 종가
재이탈은 기존 상태를 무효화한다. L3 이탈은 중간/확정을, H3 이하 재진입은
현재 확정 상태를 해제한다. 이 표시 규칙은 이벤트 판정/매매 조건을 변경하지 않는다.
40일 창에서 현재 구조가 보이지만 과거 사건일에 필요한 40일 가격을 확보하지 못한
경우에는 현재 구조만 표시하고, 단계 사건 및 최초 확인일을 만들지 않는다.
`current_structure_only`와 공란 확인일로 구분한다.

10/15/20%는 누적 상한이므로 합산하지 않는다. 별도 비중복 구간을 제공한다.
수급 개선은 기준일의 5거래일 합계가 양수이고, 겹치지 않는 직전 5거래일보다
증가한 경우이다. 과거 이벤트 행의 `flow_improving_asof`는 10/19 수급이며
각 과거 이벤트 날짜의 수급으로 해석해서는 안 된다.

## 검증 한계

최신 응답이라는 이유로 충돌을 해제하지 않는다. 공식 근거 없이 원인을
KRX/NXT 차이·기업행사·갱신 지연으로 단정하지 않는다. 공급자 최종 확정 상태는
UNVERIFIED이며 여기서 검증 통과란 확보한 자료의 운용·정합성 검사 통과이다.
미래 수익률, 성공률, 투자 우위는 계산하지 않는다.

기존 701종목과 새 수집 종목의 관측 길이는 서로 다르다. `first_evaluable_event_date`를
함께 보존하며 전체 과거 사건 수를 같은 길이의 발생 빈도로 해석하지 않는다.
기준일 현재 상태와 기준일 신규 사건은 각각 동일 날짜로 비교한다.

## 원본과 재현 범위

ZIP에는 연구용 동결 DB·선행 관측·새 가격 응답·분류 결과를 포함한다.
`analyze.py`는 ZIP을 푼 연구 디렉터리만으로도 추가 API 없이 실행할 수 있다.
`verify.py`의 운영 보존 검사는 이 GitHub 연구 브랜치의 전체 checkout에서 실행한다.
배치 실행 시 사용하는 수동 workflow는 해당 브랜치의
`.github/workflows/kis-history-probe.yml`이다. 기본적으로 이미 저장된 응답은 호출하지 않는다.
새로운 기준일·대량 추가 수집에 대한 승인으로 해석해서는 안 된다.

전체 요청 상한은 시장 데이터 공급자에 보내는 HTTP 요청을 대상으로 하며,
인증·실패·재시도·지수/공식 시세 대조를 모두 포함한다. GitHub 상태 조회/파일 전송은
시장 데이터 API 요청 수에 합산하지 않고 별도의 실행 벽시계 시간에 포함한다.

## 중간 확인 후 H3를 이미 넘은 경계 사례

원래 중간 사건을 지우거나 확정 돌파 사건을 새로 만들지 않는다. 다만 현재 종가가
H3를 이미 초과했다면 요청의 “고점 돌파 전 중간 후보”와 구분한다.
`current_close_above_H3`, `middle_before_breakout`으로 나타내며,
`middle-boundary-cases.csv`에 별도 보존한다. 이 경우 원래 중간 구조 유지 통계에는
남지만 핵심·확장 “돌파 전” 후보에는 넣지 않는다. 이는 기존 H3 기준으로 현재
상태를 구분한 것으로, 새 수치 임계값이나 변경된 스윙 규칙을 도입한 것이 아니다.
