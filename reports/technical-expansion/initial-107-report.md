7종목의 수정·미수정 최신 KRX 종가는 같았고, KRX 공식 일별 OHLCV 및 KIS J 수급 응답의 종가와도 일치했다. 따라서 6종목은 기존 값과 통합 가격의 대응 관계를 확인했다. 그러나 과거 수집 요청 로그에는 J가 남아 있어 **당시 공급자의 응답 경로나 수정 과정을 증명한 것은 아니다**. 미래에셋증권의 기존26,350원은 현재 통합26,450원 및 KRX27,050원 모두와 달라 보류한다. 기존 전체 2,042종목 종가 문제까지 해결됐다고 일반화하지 않는다.

KIS 공식 명세에는 J/KRX·NX/NXT·UN/통합, 수정0·원주가1이 명시돼 있다. 일봉·수급 응답에서 공식 최종 확정 필드는 확인되지 않았고, 수급 설명은 15:40 이후 가집계이며 산출 시각이 일정하지 않다고 명시한다. KRX 일별 자료의 값 일치는 `CROSS_VALIDATED_DAILY`로 저장하지만 `VERIFIED`로 올리지 않는다. 경과 시간이나 반복 응답만으로 확정하지 않는다. 확보된107종목 중 최종확정 미확인107건, 원본 가격차이 미해결86건(중복 집계)이 판정 보류 사유다.

공식 명세·실제 시장별 응답: [공급원 검증 JSON](provider-evidence.json). 독립 KRX API 직접 응답: [7종목 원본 대조](local-krx-crosscheck.json).

## 기업행사와 개인 매매일지

KIS 공식 공개 예탁원 API(액면교체·합병/분할·무상증자·감자) 4개에서 각100건, 총400건을 실제 수신했다. 확보한107종목 중7종목에서 관련 관측 기록을 연결했다. 원문 record_date는 권리 기준일로 보존하며 실제 거래 효력일로 임의 해석하지 않는다. 조정 비율·재평가 사유도 일봉과 함께 저장한다.

**첫 페이지의 일부 기간 자료이므로 전체 기업행사 이력·권리락 검증은 미완료다.** 이미 받은 기업행사는 다음 조회 실패나 페이지 이동 시에도 보존한다. 개인 보유 수량·평균매수가를 자동 변경하지 않는다. Supabase 미연결이어서 인증·사용자별 RLS·개인 기록 영구 저장·보유종목 자동 수집 실운영은 미검증이다. 거래비용도 미설정이며 청산 조건과 비용 미설정을 구분하는 기존 엔진을 유지했다.

## 자동화·저장·웹

- 기존 수급·재무·공시 DB와 테마 자료, 20:30/23:30 워크플로 및 기술 규칙 해시 일치. 기술 원본과 기존 평가 엔진은 보존했다.
- 별도 gzip 캐시, 완료 종목 건너뛰기, 신규 날짜+겹침 확인, 조정 발생 시 동일 기준 창 재수집, 실패 후보 분리, 체크포인트 게시를 구현했다.
- 평일23:45 및 다음날00:45·01:45·02:45 KST에 분할 진행. 기존 수급 게시 성공 이벤트도 유지. 같은 KIS 동시성 그룹으로 충돌 방지. 예약 시간은 지연될 수 있다.
- 개인 작업은 별도 Supabase에만 저장하며 미설정이 공개 수집을 막지 않는다. 최초 매수일 전160일을 확보하도록 개인 조회 기간을 늘렸고 캐시를 재사용한다.
- **수동 Actions 실제 실행은 성공. 아직 도래하지 않은 예약 실행과 신규 거래일 증분 운영은 검증 완료로 표시하지 않는다.**
- 현재 공개 캐시 약1.21MB, 동일 평균으로 전체 약27.4MB 예상. 종목별320일·요약60회로 제한한다. Git 이력의 장기 누적은 별도 관찰이 필요하다. 공개 저장소의 표준 runner를 유지했고 유료 서비스는 추가하지 않았다.
- 웹 연결 검사에서 이전 기술 모듈이 메모리에 남는 문제를 재현하고 수정했다. 모듈을 다시 불러오도록 한 뒤 공개 앱과 로컬에서 새320일 자료 및 KRX 교차 확인 표시를 확인했다.
