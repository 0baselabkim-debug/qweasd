## KRX 403 및 재개

- 기존 AUTH_KEY 방식과 공식 두 URL을 유지했다. 키 변경·IP 변경·프록시 우회·비공식 스크래핑은 없었다.
- 11:15 KST의 403 이후 실제 예약·수동 실행에서 200 응답으로 재개됐다. 현재 인증이 사용 가능한 근거는 실제 응답이며, 과거 403의 원인은 확정되지 않았다. 키 오류나 영구 권한 상실로 단정하지 않는다.
- `REFERENCE_RECEIVED`, `REFERENCE_TEMPORARY_FAILURE`, `REFERENCE_AUTH_ERROR`, `REFERENCE_SCHEMA_ERROR`, `REFERENCE_DATE_MISMATCH`, `REFERENCE_NOT_AVAILABLE`를 구분한다. 정상 동일 날짜 캐시 사용은 `CACHED_SAME_DATE`로 별도 표시한다.
- 401/403은 1시간부터 최대 24시간, 전송 장애·408·429·5xx는 15분부터 최대 24시간 백오프한다. 한 시장에서 접근 거부가 나면 그 실행의 다른 시장·날짜 요청도 중지한다. 정상 시장의 응답이 다른 시장의 반복 거부 횟수를 초기화하지 않도록 테스트했다.
- 실제 요청 여부·HTTP·UTC 시각·응답 해시·재시각을 저장한다. 인증값과 오류 원문은 저장하지 않는다. 이후 정상 수신하면 재개한다.
- 일반 검증의 기존 동일 날짜 캐시 허용 정책은 유지한다. **충돌 복구는 새 KRX 조회 필수**이며, 장애 중 오래된 응답으로 새 조회를 대신하지 않는다. 기존 유효 원본과 관측별 해시는 보존한다.
- KRX 공개 첫 화면은 200, 상세 안내 화면은 403이었다. GitHub Secrets 등록 메타데이터도 조회 권한이 없어 변경 시각을 확인하지 못했다. 이는 인증된 데이터 API의 실제 200 성공과 별개다. 최종 공표 시각을 새로 확정한 것은 아니므로 공급자 `UNVERIFIED`를 유지한다.

## DART 실제 원문 검토

새 호출은 `document.xml` 12회(6건씩 두 실행)이며, 이미 수신한 정정 원문 및 첨부 4건은 재사용했다. 기존 실패 재무 API를 똑같이 반복 요청하지 않았다.

- **079900 / 20260605000456:** 원 보고서 `20260318000902`와 연결·별도 재무제표 본문의 정규화 텍스트·숫자 순서·단위가 동일했다. 정정표에는 위험관리 주석의 통화 단위/기재와 감사 관련 날짜 정정이 있다.
- **003160 / 20260605000334:** 원 보고서 `20260312001121`와 연결·별도 재무제표 본문이 동일했다. 정정표에서 보통주 배당률 50.00→0.50, 20.00→0.20의 비율 단위 정정을 확인했다.
- API가 정정 접수번호로 재무를 반환한다는 근거가 아니므로 두 재무 실패 상태를 유지했다. 다른 접수번호의 재무를 이름만 바꿔 새 정상 버전으로 등록하지 않았다. 주석 변경까지 ‘영향 없음’으로 선언하지 않았다.
- 첨부정정 12건 중 4건(054950·126880·002460·033160)은 정확한 기업·접수번호의 감사 원문을 확보했다. 나머지 8건은 HTTP 200 안의 DART 상태 014(파일 없음)였다. ZIP 오류나 성공한 감사 검토로 바꾸지 않았다.
- 감사 원문의 별도/연결 문서명과 의견 문맥을 보존했지만, 원 보고서 대비 정정 영향 검토까지 완료한 것은 아니다. 따라서 12건의 `held_attachment_only` 상태를 유지했다.

`correction-review.json`, `dart-source/`에 원문·해시·주석 정정표·재무 본문 비교를 보존했다. `document_source_reviews`와 감사 이벤트에 검토 근거 14건만 추가했으며, 기존 재무·사업 내용·테마·실패 상태는 보존했다. 감사의견이 적정하다는 사실을 재무 위험 없음이나 투자 적격으로 해석하지 않았다.

## 남은 사항과 필요한 조치

1. 나머지 활성 충돌 및 미검토 자료는 기존 검증 기준과 백오프 안에서 순차 처리한다. 다음 예약은 14:17 KST 예정이나 GitHub 지연 가능성이 있다. 정상 기준자료가 오지 않으면 안전 중단한다.
2. 미완성 업종은 25일 전체 구성종목 자료가 부족해 보류다. `sector-gaps.csv`로 필요한 날짜·종목을 확인할 수 있다.
3. 재무 API의 두 정정 접수번호와 미제공 감사 첨부 8건은 공식 근거가 더 필요하다. 기존 정상 버전은 계속 사용하며 첨부정정 영향은 검토 대기다.
4. 시장 전체 투자자 수급은 최신 공식 공개 예제 두 파일에서도 원화 배수·KRX/NXT 범위가 명시되지 않아 `unit_scope_pending`을 유지한다. 문의 초안은 `provider-questions.md`이며 발송하지 않았다.
5. 투자 적격성 규칙은 미승인 상태를 유지한다. 자동 매매나 새 자격 증명·계정은 추가하지 않았다.

사용자에게 코드 수정이나 키 재발급을 요구할 단계는 아니다. 재발하는 접근 거부의 정확한 공급자 사유, 미제공 공시 자료, 시장 수급의 공식 정의는 별도 확인이 필요하다. 위 근거가 확보되기 전에는 보류를 임의로 해제하지 않는다.
