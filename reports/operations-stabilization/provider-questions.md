# 확인이 필요한 공급자 근거 — 문의 미발송

## KRX 접근 거부

2026-10-16 11:15 KST에는 같은 공식 일별 URL 두 곳이 HTTP 403을 반환했고, 11:50 이후 기존 GitHub Actions 연결에서 200과 해당 거래일 자료를 다시 받았다. 이 사실만으로 403의 발급 주체·키 오류·요청 제한·일시적 서비스 장애 중 하나를 단정할 수 없다. 인증값을 변경하지 않았으며 프록시/IP 변경을 시도하지 않았다. GitHub Secrets의 등록 메타데이터 조회 권한은 없으므로 등록 변경 시각을 확인했다고 주장하지 않는다. 현재 인증 유효성의 근거는 실제 승인된 두 API의 정상 응답이다.

재발 시 확인 요청: 아래 공식 URL의 AUTH_KEY 인증 요청에서 해당 시각에 403을 반환한 정책/오류 코드, 분당·일별 제한, 허용된 앱/IP 조건, 재시도 권고 간격. 키 값은 첨부하지 않고 실행 ID·UTC/KST 시각·응답 해시만 제공한다.

- `/svc/apis/sto/stk_bydd_trd?basDd=20261015`
- `/svc/apis/sto/ksq_bydd_trd?basDd=20261015`

공개 KRX 첫 화면은 200이나 실제 안내 화면은 이 환경에서 403이었다. 문서 접근 성공과 인증된 데이터 API 성공을 혼동하지 않는다. 공표 최종 확정 시간을 새로 확인한 것은 아니며 기존 운용 검증과 `UNVERIFIED` 구분은 유지한다.

## KIS FHPTJ04040000

공식 공개 저장소의 `inquire_investor_daily_by_market.py`, `chk_inquire_investor_daily_by_market.py`를 확인했다. 시장 입력과 필드명 설명은 있으나 다음 내용의 명시적인 근거는 없었다. 기존 API 명세를 반복 호출하지 않았다. 두 파일과 수신 해시는 `official-documents/`에 보존했다.

1. `frgn_ntby_tr_pbmn`, `prsn_ntby_tr_pbmn`, `orgn_ntby_tr_pbmn`의 실제 원화 배수와 소수점/절사 기준은 무엇인가?
2. KSP·KSQ 및 업종코드 조합은 KRX 거래만 포함하는가? NXT/통합 거래 포함 시 장 구간과 적용일은 무엇인가?
3. `frgn_reg_*`, `frgn_nreg_*`와 외국인 합계의 관계 및 기타외국인 포함 기준은 무엇인가?
4. `orgn_*` 기관계에 포함되는 투자주체는 무엇인가?
5. 일별 응답의 가집계·확정·장후 정정 기준과 거래일 식별 방법은 무엇인가?

필드별 단위 및 시장 범위를 해당 API 문서 버전이나 공식 답변으로 받아야 한다. 종목 API의 단위를 전용하거나 다른 투자주체 금액을 차감해 생성하지 않는다. `unit_scope_pending`과 대시보드의 미확보 상태를 유지한다.
