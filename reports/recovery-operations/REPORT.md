## 요청 예산과 재개

종전 BoundedAPI는 논리 요청마다 3회, 최초 인증까지 6회를 예약한 뒤 미사용분을 돌려주지 않았다. 기존 실험은 실제 20회에 예약 60회가 소진됐다.

이제 KIS의 실제 HTTP 전송 직전에 한 슬롯을 차감한다. 인증, 인증 재시도, 일반 재시도, 전송 예외를 모두 계수한다. **최대 60회, 새 요청 시작 예산 240초, 호출 간격 1.05초, 공유 concurrency, 인증 직렬화**를 유지했다. 미사용 재시도 예약은 0이다. KRX는 별도 최대 두 날짜×두 시장(4요청)이며 실제 상태를 따로 기록한다.

성공 응답은 즉시 내용 해시별로 저장하고 중단 세션의 원본 해시·응답 인덱스를 남긴다. 재개 시 수정주가 겹침 구간과 같은 날짜 원주가를 새로 확인한다. 두 기준 응답의 해시 조합과 일치하는 세대의 저장 페이지만 재사용한다. 다른 수정주가 관측 시점의 페이지를 섞지 않는다. 옛 형식의 단일 중단 관측은 두 기준 응답을 재확인한 경우에만 재사용한다.

## 거래 활성도 연결과 보존

기술 캐시의 최신일 수락과 DB의 과거일 충돌 마스킹은 별개였다. 10월 15일 기술 복구만으로는 10월 14일에 설정된 거래대금 마스크가 사라지지 않았다.

- 이미 검증된 현재 자료에서 과거일 작업을 만들더라도, 수락 증거와 계산값은 제거하고 그 날짜의 실제 20일 수급과 날짜 이하의 이력만 넣는다. 별도의 정확한 날짜 KIS J 수정주가·원주가·KRX OHLCV·수급·해시 검증을 모두 통과해야 한다.
- 원본 `prices`, 수급, 재무, 업종 및 기존 충돌 목록은 보존한다. `liquidity_price_evidence`는 **같은 종목·날짜의 거래량/거래대금이 원본과 동일**하고 전체 가격 번들이 검증된 경우에만 그 거래대금을 사용할 수 있게 한다. 기존 종가·시총을 다른 공급자 값으로 섞거나 과거 전체 충돌을 해제하지 않는다.
- 25일 완전성과 섹터 전체 구성종목 요건은 유지한다. 구성종목 일부만 회복됐다고 완전한 섹터 지표로 표시하지 않는다.

## 운영 상태 및 남은 사항

- 예약 검증 뒤 복구 경로는 유지하고, 실제 8건 시험보다 작은 **회당 최대 4건**으로 설정했다. 물리 요청/시간 한도는 그대로다. 날짜별 순환, 예산 중단 재개, 오류 백오프, 성공 건 제외, 짧은 이력/수급 부족 큐 분리를 적용했다.
- 평일 5회, 토요일 오전 1회이므로 회당 4건이면 평일 최대 20건·토요일 최대 4건은 **시도 상한**이다. 과거일/최신일 작업, 실패·백오프·예산 중단을 포함하므로 신규 종목 검증 성공 수와 같지 않다.
- 실제 처리량과 새 거래일 유입량은 아직 여러 거래일 운영으로 입증되지 않았다. 단일 기준일의 수동 시험으로 대기는 줄었지만, 매일 대기가 감소한다고 단정하거나 완료 날짜를 약속하지 않는다.
- 시장 전체 투자자 수급은 `unit_scope_pending`. FHPTJ04040000의 금액 배수, KRX/NXT 범위, 외국인 분류, 일별 정정 기준을 해당 API에 대해 공식 확인해야 한다. 종목 API 단위 전용·차감 추정은 하지 않았다. 기존 명세 반복 조회는 복구 워크플로에서 제거했다. 문의는 발송하지 않았다.
- 투자 적격성은 `approved_by_user=false`, 빈 `rules`를 유지한다. 감사의견 표본 3기업 확보와 최종 규칙 승인은 별개이며, 중대한 재무 위험 자료 등도 미확보다. 임계값을 활성화하지 않았다.
- 거래비용·기업행사 미확보를 임의 값으로 채워 매도 가이드를 활성화하지 않았다. 전체 가격 불일치, 미검토 자료, 이력 부족과 섹터 완전성은 남아 있다.

최종 수치·CI·예약 이벤트 확인 결과는 이 보고서의 아래 완료 시점 기록과 `verification.json`, `release-validation.json`을 따른다.
