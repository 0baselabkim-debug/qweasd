# 정규 수집 시간·KIS 호출 최적화

기준 main `5998be3`, 최종 실행 코드 `c00efebe0e3363c6c45ba5ed8104d3284ef4a054`. 2026-10-16 작업. [공개 앱](https://0baselabkim-debug-qweasd-app-nuf4kg.streamlit.app/).

## 적용 내용

- 평일 **18:30 / 21:00 KST** → UTC cron **`30 9 * * 1-5` / `0 12 * * 1-5`**. 정규 수집의 옛 두 cron은 제거했다. 원격 main 내용도 대조했다([배포 설정](deployed-schedule.json)).
- 코드 시작 제한도 18:30으로 변경했다. 미래·주말·장 시작 전은 거부하고 공식 휴장일을 조회한다. 지연된 schedule은 runner 시작일 대신 실행 생성일에 연결한다. 다음 달력일 09:00 이후의 최신 시세를 전날 종가로 사용하지 않는다. 당일 관측 업종 마스터 없이 과거 구성을 만들지 않는다.
- 기존 공유 `kis-validation-auth`, `cancel-in-progress: false`, `queue: max`, 1.05초 호출 간격, 작업자 2개를 유지한다. 실행당 140분 이후 새 종목 작업을 시작하지 않고 미완료로 남긴다. 이미 진행 중인 요청·저장·검증 시간은 별도다.
- 원천 정합성을 통과한 종목만 저장한다. 성공 종목·정상 제외는 같은 날짜에 다시 조회하지 않는다. 미완료만 후속 시도하며 21:00 재시도에서도 같은 체크포인트를 사용한다. 준비되지 않은 당일 지수는 성공 캐시로 고착시키지 않는다.

## 두 번 조회 경로와 검증

공식 명세를 GitHub Actions에서 받아 확인했다([원문 응답과 URL](probe/specs.json)). 모든 종목 요청은 **J=KRX**이며 NX/NXT 또는 UN/통합으로 대체하지 않는다.

| 응답 | 활용·시간 기준 | 검증 |
|---|---|---|
| `FHPTJ04160001.output2` | 날짜 명시 외국인 수급·종가·거래량·거래대금 | 정확한 거래일, 순매수=매수−매도 금액/수량, 기존 외국인 금액 ×1,000,000 환산 유지 |
| `FHKST03010100.output2` | 날짜 명시 수정주가 이력, 거래량·거래대금 | 중복·미래 날짜·불량 값 차단, 당일 수급과 종가·거래량·거래대금 일치 |
| `FHKST03010100.output1` | 최신 시세·정밀 상장주식수·HTS 시가총액 | 날짜가 없는 헤더임을 유지. 당일 날짜 있는 관측과 일치, 종목코드·관측 시각·당일 마스터 주식수·종가×주식수 대조 |
| `FHKST01010100.output` | 예외 시 추가 현재가 | 필드 부족·헤더 불일치·공식 업종 추가 확인 때 사용. 같은 검증을 통과하지 못하면 실패 |

시가총액은 기존 **HTS 시총 ×100,000,000원** 값을 유지하고, 종가×실제 상장주식수와 기존 허용 오차를 그대로 비교한다. 마스터의 천주 단위를 곱해서 정확한 주식수를 만들어내지 않는다. 공식 마스터 업종이 없는 경우 현재가 응답의 업종 우선순위를 보존한다.

명세의 가격 응답 `hts_avls`·`acml_tr_pbmn` 설명에는 금액 배수가 적혀 있지 않고, 수급 응답 `acml_tr_pbmn`에는 ‘백만원’이라는 표기가 있다. 실제 표본의 수급 거래대금 원문은 가격 응답의 원화 거래대금과 그대로 일치했다. 따라서 이번 작업에서 그 표기만으로 기존 거래대금을 재환산하지 않았다. **기존 검증된 환산과 실제 응답 간 동일성 검사를 유지**하며, 수급 거래대금의 명세 표기 차이는 공식 설명 보완이 필요한 사항으로 남긴다. 외국인 순매수 금액과 전체 거래대금은 서로 다른 필드다.

수급과 일별 가격이 다르면 추가 현재가로 덮어 맞추지 않는다. 최신 가격 한 값을 과거 이력에 끼워 넣지 않는다. 공급자 최종 확정 플래그가 확인된 것은 아니므로 **UNVERIFIED 유지**다. 18:30은 수집 시도 시각이며 공식 최종 확정 시각이라고 주장하지 않는다. 미확보·불일치·필수 검증 실패가 있으면 정상 게시본을 유지한다.

동일 VM에서 단회 측정한 값이며 운영 서버 성능 보장이나 통계적 평균이 아니다. 후보 DB의 해시도 기존 정상 게시본과 같았고 원시 수급·가격·시총·재무·업종·기존 평가 결과를 바꾸지 않았다. 실제 새 10/16 전체 수집/검증/게시 시간을 측정한 것은 아니다.

과거 실제 전체 실행 [38731200188](https://github.com/0baselabkim-debug/qweasd/actions/runs/38731200188)은 **2,430종목 수집 7,409 HTTP 관측 / 7,792.33초(129분52초)**였다. 그러나 체크포인트 저장 단계에서 실패하여 **그 실행의 게시 단계는 건너뛰었다**. 과거 로그에 attempt 필드가 없어 정확한 재시도 수는 확정하지 않으며 EGW00201 응답 2건만 확인했다([과거 실행](previous-full-run.json)).

체크포인트는 이제 실행 중 checkout을 전환하지 않고 별도 Git 인덱스·커밋으로 저장한다. 강제 push하지 않아 동시 변경 시 안전하게 거부된다. 종목별 결과는 해시와 날짜가 있는 저널에 fsync하고, 중단된 마지막 불완전 행만 제외한다. [실제 Actions 38869407015](https://github.com/0baselabkim-debug/qweasd/actions/runs/38869407015)에서 기존 2,430종목 자료 저장 → 동일 자료 재실행(unchanged)을 확인했다. 작업 HEAD 유지, 시장 API 0회, 별도 증거 브랜치만 생성했다([결과](probe/checkpoint.json)).

**완료 예상:** 실제 18:30 시작, 대부분 2회 검증 통과, 응답 지연·재시도가 작다는 조건에서 약 **20:00~20:20**을 계획 범위로 본다. 최저 호출 간격 85분에 공통 요청·제외·예외·검증·게시를 더한 추정이다. 전 종목 필수값이 끝내 일치하지 않으면 21시 전 게시 대신 이전 게시본을 보존한다. 예약 지연, 대규모 불일치 및 실패를 포함한 완료 보장은 아니다.

## 아직 실측하지 않은 사항

1. 오늘 **18:30/21:00 실제 schedule 실행**, 새 날짜 전체 수집·검증·게시 완료: 아직 예약 전이다([시간 확인](schedule-status.json)).
2. 전체 2,430종목의 2회 성공 수·추가 조회 예외 수·실제 완료 시각: 소규모 표본 결과로 대신하지 않는다. 새 `call_summary`, 단계별 시간, 게시 ledger에 집계하도록 구현했다.
3. 공급자 최종 확정 시각과 일부 명세 단위 표기: 공식 확정으로 바꾸지 않았다. 정합성 실패는 그대로 차단한다.
4. 기존 유동성 미확보·원천 충돌 및 공시 근거 부족은 별도 과제이며, 이번 시간 단축을 위해 정상 처리하지 않았다.

사용자 추가 설정·키 재발급은 필요 없다. Actions → **Daily validated dashboard refresh**에서 오늘 실행 상태를 확인할 수 있다. 수동으로 미완료만 재시도하려면 **Run workflow → collect**를 선택한다(18:30 이후 시간/공식 거래일 제한 적용). 기존 매크로·수급 필터·재무·테마와 다크 UI는 유지했고 매매 가이드·매매일지는 복구하지 않았다.
