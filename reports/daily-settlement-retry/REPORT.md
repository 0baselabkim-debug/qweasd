# 일일 수집의 제한적 공급자 정합성 재확인

## 원인과 적용 범위

2026-10-20 태원물산은 21:39 KST 관측에서 수급 종가 3,020원과 차트 종가
2,995원이 불일치했고, 21:49 관측에서는 양쪽 모두 2,995원으로 일치했다.
기존 수집은 실패 항목을 즉시 두 번째 조회하므로 이러한 갱신 시차를 흡수하지
못할 수 있었다. 공급자 내부 정정 원인은 확정하지 않았다.

## 구현

- `daily_retry.collect_pending`: 날짜가 일치하는 가격·거래량·거래대금 충돌만
  5분 후, 이어서 10분 후 재확인. 최초 조회 포함 실행당 종목별 최대 3회.
- 그 밖의 오류는 기존 최대 2회. HTTP 전송 오류 재시도는 기존 KIS 클라이언트가 담당.
- 추가 대기 합계 최대 900초이며 기존 140분 실행 예산과 다음 날 09시 날짜 창을
  늘리지 않는다. 시간 부족 시 기다리지 않고 실패 상태로 다음 기존 실행에 인계한다.
- 1.05초 호출 간격, 2개 작업자, 인증 직렬화, 공유 workflow concurrency 유지.
- 성공·제외 자료는 재조회하지 않는다. 대기 종목이 다른 준비된 종목을 막지 않는다.
- 종목별 오류 분류·누적 시도·다음 조회 시각은 동일 날짜 체크포인트에 저장한다.
  실행당 시도 상한은 다음 실행에서 새로 시작하지만 저장된 대기 시각은 준수한다.
- 실패 원문은 기존 내용 해시별 진단 기록으로 보존한다. 성공 응답만 기존 모든
  검증을 다시 통과한 후 저장하며 `UNVERIFIED`를 변경하지 않는다.
- 재확인 요약 및 잔여 대기 상태를 checkpoint의 attempts와 operations 실행 기록에 남긴다.
- 18:30 / 21:00 KST 예약, 게시 검증, DB, JSON, 화면과 수급 계산은 변경하지 않았다.

## 검증 방법

`tests/test_daily_retry.py`는 가상 시계로 대기 시간을 검증한다. 실제 저장된
태원물산 실패 응답을 두 번 재생한 뒤 실제 정상 응답을 재생하는 별도 검증도 수행한다.
이는 신규 API 수집이나 실제 예약 운영 성공이 아니다. 최초 불일치 2건을 그대로
보존하고, 마지막 응답의 가격·수급·시가총액을 기존 `validate_bundle`로 검증한다.
원본 수치, 순매수 단위, 거래일, KRX 범위, 최종 확정 상태는 바꾸지 않는다.

추가 API 호출은 하지 않았다. 이미 게시된 10월 20일 자료를 다시 수집하거나
게시하지 않았다. 다음 신규 거래일의 실제 예약 처리 결과는 아직 검증 전이다.
계속 불일치하는 경우 이전 정상 게시본을 유지하며 자동으로 값을 선택하지 않는다.
