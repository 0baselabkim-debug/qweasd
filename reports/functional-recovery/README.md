## 수정

- 동일 기준일 캐시 선택에서 검증된 긴 개인 이력이 공개 320일 캐시에 가려지는 문제를 수정했다. 날짜를 먼저 비교하고, 같은 날짜에 검증 상태·이력 길이를 비교한다. 공개/개인 겹치는 날짜의 원본 일봉 또는 수급이 다르면 선택하지 않고 보류한다. 종목코드 불일치도 제외한다.
- 기술 갱신 요청 RPC 실패가 이미 읽은 분석 자료를 지우지 않도록 분리했다. 실패는 화면 근거에 표시하고 다음 조회에 재시도한다. 비공개 조회 실패 시 공개 자료만 별도로 평가하되 동일한 검증 게이트를 적용한다.
- 매매일지는 최신 수급 기준일보다 오래되지 않은 동일 날짜 일봉·수급 묶음일 때만 평가손익·매도 가이드를 산출한다. 과거 검증 종가를 최신 가격으로 표시하지 않는다. 5분 재조회 중 더 최신의 검증 캐시가 도착하면 평가할 수 있다.
- 웹 검사의 NAVER 고정 성공 문구 가정을 실제 원본의 대조 결과·일별 검증 상태·보류 사유와 대조하도록 수정했다. 불일치/미확보를 확인으로 표시하면 여전히 실패한다.

## 증거

- `data-audit.json`: 실제 캐시 2,432개 수급 전부 스냅샷과 일치. 최신 대상 2,430종목 중 데이터 게이트 통과 216, 관망 212, 판정 보류 2,218. 과거 기준일 캐시 2개는 현재 대상에서 제외. 매수 판정 0개를 오류나 성공으로 임의 변경하지 않았다.
- 7개 실제 종목의 지표·피벗·손익비·미래 데이터 미참조 독립 계산 통과. 원본 DB/시세/수급/매크로/테마/가중치/매매 규칙 변경 없음. 시장 API 추가 호출 0회.
- `local-final/result.json`: 실제 Streamlit + Chromium, 1920/1440/768/390px. 화면 이동, 더블클릭/터치, 검색/정렬, 탭 유지/닫기, CSV 실제 값, 재무·테마, 매수 근거·상태, 화면 넘침 검사.
- `journal/result.json`: 별도 합성 테스트 서버의 로그인 UI, 추가/취소, 저장 실패 재시도, 분할매수, 수정/삭제, 사용자 화면 분리, 모바일 팝업 통과. 실제 Supabase/RLS/영구 저장 검증을 의미하지 않는다.
- `live-before/result.json`: 기존 공개 앱 실제 접속 시도는 환경 프록시의 CONNECT 403 / ERR_TUNNEL_CONNECTION_FAILED로 차단. 로컬 성공으로 공개 배포 성공을 대체하지 않는다.

재현: `python -m pytest -q`, `python scripts/audit_dashboard_recovery.py`, 로컬 앱을 실행한 뒤 `BROWSER_EXECUTABLE=/usr/bin/chromium DASHBOARD_CHECK_URL=http://127.0.0.1:8501 python scripts/check_live_dashboard.py`. 매매일지 합성 검사는 `tests/journal_browser_harness.py`를 8510 포트로 실행한 뒤 `scripts/check_journal_local.py`를 사용한다.

## 미완료 범위

현재 환경에 Supabase 인증 설정/테스트 계정이 없어 실제 저장, 재로그인·재배포 유지, DB RLS 검증은 실행하지 못했다. 새 계정·권한·서비스를 만들지 않았다. 기업행사 완전성 및 실제 거래비용 미검증에 따른 매도 보류도 유지한다. 가격 정합성/공식 대조 미완료를 임의 해제하지 않았다. 금융 거래는 수행하지 않았다.

최종 테스트 결과는 `completion.json`에 기록한다. 원격 저장소 반영 여부는 최종 응답에서 별도로 확인한다.
