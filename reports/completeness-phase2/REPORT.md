## 원인과 코드 개선

1. 기술자료의 최신일 수락과 대시보드의 과거 25일 마스크는 별도다. 이미 구현된 날짜별 증거 게시 경로를 그대로 사용했다. 원본 종가를 교체하지 않고, 정확한 날짜의 KIS J 수정/원주가, KRX OHLCV 6필드, 20일 수급, 해시와 전체 검증을 통과한 후보의 거래량·거래대금이 원본과 같을 때만 해당 관측을 계산에 반영했다.
2. 과거 작업의 생성 순서를 오래된 날짜 우선, 이후 구성종목 수 / 남은 검증 수로 정했다. 코드 순서만으로 작은 업종부터 처리하는 것을 피한다. 기존 날짜 순환·백오프·재개 체크포인트·완료 작업 제외를 유지했다.
3. 가격은 일치하지만 수락이 끝나지 않은 자료는 저장 수급 응답으로 전체 검증을 시도하는 경로를 연결했다. 이 분기는 단위테스트에서 HTTP 0회와 재실행 제외를 검증했다. 이번 실제 14종목은 가격 이력 정합성 확인이 필요해 새 가격 후보를 사용했으며, 저장 페이지·수급 응답 재사용은 0건이었다. 단위테스트 성공을 실제 무호출 복구 성공으로 표현하지 않는다.
4. KIS 60회 물리 요청, 240초 새 요청 시작 제한, 1.05초 간격, 인증 직렬화와 공유 concurrency를 유지했다. 검증 후보 통과와 게시 성공을 분리하고, 같은 run_id의 종목·섹터 지표 증가량만 연결했다.
5. 요약 집계의 동일 검증을 실행 안에서 재사용했다. 실제 저장 번들 2,432개(현 기준일 대상 2,430개)로 비교한 결과, 관측 시각 외 집계·상태값은 모두 같았다. 단일 로컬 측정 140.43→107.26초(약 24% 감소)이며 전체 Actions 실행 시간의 고정 단축률을 뜻하지 않는다.
6. 감사 도중 소스 커밋/DB가 바뀌면 결과를 거부하도록 했다. 최종 감사는 고정된 코드·자료로 실행했다.
